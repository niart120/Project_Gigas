# 異常時の記録を確認する

GIGASは通常運用でも診断ログを保存します。記録を有効にする設定や診断モードへの切替は不要です。

## 保存場所

エクスプローラーのアドレス欄に`%LOCALAPPDATA%/GIGAS/logs`を入力します。設定ファイルの場所を変更している場合は、その親フォルダーの`logs`を確認してください。

起動ごとに`20261117T093000Z_12345`のようなフォルダーがあり、UTCの開始日時とプロセスIDを示します。内部の`gigas.jsonl`が最新、`gigas.jsonl.1`から`.9`が古いログです。JSONLは1行1件のJSONで、テキストエディターで開けます。

## 調査の進め方

1. 異常が発生した時刻と、その後に行った停止・再開などの操作を控えます。ログの`timestamp`はUTCです。日本時間はUTCに9時間を加えます。
2. 該当する起動のログで`ERROR`・`WARNING`を探し、その前後の操作要求・結果・状態変化を確認します。多重起動時は複数の起動フォルダーを確認します。
3. `thread_id`・`turn_id`をCodexの会話履歴と、`operation_id`・`reference`を作業フォルダーの`records/<thread-id>/events.jsonl`や観測画像と照合します。共通ログだけで会話本文や全入力履歴を再現することはできません。

ログは各起動で約100 MiB、終了済み直近10回分が保持されます。調査に必要なログは古くなる前に別の場所へコピーしてください。自動整理はゲーム記録やCodexの履歴には適用されません。

## 保存失敗の通知

「診断ログ保存失敗」が出てもゲーム操作は継続します。通知詳細で対象パスと失敗理由を確認し、空き容量や書き込み権限を確認してください。保存先を起動時に作れなかった場合は、原因を解消した後にGIGASを起動し直します。途中の書き込み失敗は後続のログで再試行され、成功すると復旧が記録されます。保存できなかった期間の記録は復元できません。

既知の認証情報は除外しますが、ログにはパスや外部サービスが返した詳細が含まれます。第三者へ渡す場合は内容を確認してください。外部サービスが原因を返さなかった場合は、ログから根本原因まで特定できるとは限りません。
