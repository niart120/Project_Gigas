# 映像プレビュー

キャプチャーデバイスから映像を取得し、最新の画像をプレビューへ表示します。[画像観測・ゲーム操作](codex.md#ゲーム操作)にも同じ取得元を使います。

## 設定

「設定…」を開くと、未接続なら機器一覧を非同期に取得します。「I/O」で機器の表示名・取得FPS・取得解像度を選び、「適用」を押します。取得中に開いた場合は既存の候補を使い、プレビューを継続します。識別子を手入力する必要はありません。表示FPS・プレビュー方式・ウィンドウサイズは「一般」で変更します。FPSの範囲と保存値は[設定](settings.md)を参照してください。

「接続」→「映像」メニューでも、開いた際に一覧を取得して機器を選べます。取得中は既存候補を使います。選択すると設定画面と同じ保存・適用処理へ進みます。設定はモーダルのため、メニューから選ぶ場合は設定画面を閉じてください。メニューのチェックは保存機器を示します。

## New Nintendo 3DS XL

Windows で対応基板を1台だけ USB 接続し、「I/O」の機器欄か「接続 → 映像」で「New Nintendo 3DS XL (ponkan)」を選びます。機器欄から選んだ場合は「適用」を押します。取得元の一覧には、ボードを外しているときもこの項目が表示されます。ドライバーを利用できないときは基板の D3XX ドライバーを確認し、もう一度接続してください。接続操作中はボード構成を変えないでください。

保存した ponkan 接続で起動した直後は、カメラ候補が未取得の場合があります。切替先のカメラが一覧にない場合は、いったん「未接続」を適用してから映像メニューを開くか、「一覧更新」でカメラを選びます。

## 接続と切断

機器欄は保存する取得先です。停止中や接続失敗後も保存機器を選択表示し、実際の接続状態は主画面下部に表示します。候補にない保存機器も保持し、別機器へ自動変更しません。

起動時は保存済み機器へ一度接続します。設定画面を開くだけでは取得を開始しません。無変更のOK／適用、または映像・ウィンドウサイズ・プレビュー方式・表示FPSの変更では、選択中の機器へ接続を試みます。推論要約など、映像表示に関係しない項目だけの変更では停止中の映像を開始しません。取得中で取得先・取得FPS・要求解像度が同じなら、再接続しません。条件を変える場合は、必要な保存と旧取得の解放を確認してから新しい取得を開始します。

停止するには設定で「未接続」を適用するか、「接続」→「映像」で「未接続」を選びます。保存機器も空になります。接続・切替中でも、保存処理の完了後に未接続を適用できます。未開始の接続予定を取り消し、開始済みの取得は解放を確認します。

保存失敗では現在の取得を維持します。保存後の接続失敗では保存値を保持し、同じ機器の再選択・再適用で再試行できます。旧機器へ自動復帰しません。「OK」は保存成功と反映要求の後に閉じ、接続成功を待ちません。「適用」は画面を維持します。キャンセルは未提出の編集を破棄して閉じ、提出済みの保存・適用は継続します。

機器一覧の更新と接続は同時に実行しません。失敗の理由は「表示」→「通知…」から再確認できます。通知を閉じても、終了未確認の状態を正常終了として扱いません。

ステータスバーの映像側には現在の機器名と接続状態、Codex側には実際の接続・実行状態を表示します。モデルと推論量はメッセージ入力枠内に表示します。映像欄とCodex欄の境界はドラッグでき、状態表示の位置も追従します。

## 取得解像度

| 選択 | 機器への要求 |
|---|---|
| 自動 | 幅・高さを指定せず、ドライバーが返す画像を使う |
| HD | 1280×720 |
| FullHD（既定） | 1920×1080 |
| WQHD | 2560×1440 |
| 4K | 3840×2160 |

固定値は機器への要求であり、実際に届く画像の寸法を保証しません。要求と異なる有効な画像が届いた場合も、実寸法と画素を保って共有します。指定寸法になるようにアプリで黒帯を付けたり、拡大・縮小したりはしません。「自動」も最大・最適解像度を探索する機能ではありません。

接続先や信号を変えた後に画像を取得できなくなった場合は、未接続にしてから機器を選び直します。取得方式・機器識別・対応する画像寸法は[映像取得API](../design/interfaces/video-api.md)を参照してください。

## 表示サイズ

「表示」メニュー、または設定の「一般」タブから選びます。どちらも同じ設定を保存し、成功後に表示を変更します。設定画面が開いている間や設定保存中は、メニューでの変更を停止します。

| 選択 | ウィンドウの希望寸法 | 映像側の初期希望幅 |
|---|---|---|
| HD | 1280×720 | 768 |
| FullHD（既定） | 1920×1080 | 1280 |
| WQHD | 2560×1440 | 1600 |
| 4K | 3840×2160 | 2560 |

プリセットは最初のウィンドウサイズと左右の配分に使い、画面の作業領域へ収めます。その後はウィンドウや中央の仕切りの変更に合わせて、右上の映像枠を16:9で広げます。映像の下には目標と今回の作業を表示します。プリセット寸法を拡大時の上限にはせず、表示サイズを変えても取得画像の寸法や接続世代は変わりません。

## プレビュー方式と表示FPS

「一般」の「プレビュー方式」で表示時の比率調整を選びます。「レターボックス」は画像全体の縦横比を保って枠へ収め、残る領域に黒い余白を付けます。「ストレッチ」は縦横それぞれを枠へ合わせます。例えば4:3の画像を16:9の枠へ表示すると、レターボックスでは左右に黒帯ができ、ストレッチでは横へ広がります。画像の切り抜きや、入力画像に既に含まれる黒帯の除去は行いません。

プレビューは取得した最新1枚を表示します。表示が遅れた場合は途中の画像を省き、最新画像へ進みます。表示FPSは更新頻度の上限です。切断・取得失敗時は表示FPSの次回更新を待たずに画像を消去します。

表示のための拡縮は、取得解像度が「自動」の場合も取得画像を書き換えません。取得時刻はPC側で画像を受け取った時刻であり、ゲーム画面が生成された時刻やキャプチャーデバイス内部の滞留時間を保証しません。観測用の変換・保存・MCP応答は[記録付き観測](../design/data/recorded-observation.md)で扱い、プレビュー設定を観測画像の設定としては扱いません。

## 終了

アプリの終了時は映像取得も停止し、機器を所有する処理の終了と資源の解放を確認します。正常終了の待機期限を超えた場合は取得プロセスを強制終了します。強制終了と機器APIによる正常解放は、取得サービスの状態で区別します。

「終了未確認」は、取得プロセスの終了、またはアプリ側の共有メモリや通信資源の解放を確認できていない状態です。この状態ではアプリを正常終了した扱いにせず、再接続も行いません。
