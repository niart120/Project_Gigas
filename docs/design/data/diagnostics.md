# 共通診断ログ

診断モードを切り替えず、アプリの起動から終了まで操作の節目と異常を常時記録する。会話本文・保存済みターンの状態やエラー・GoalはCodex App Serverを正本とする。GIGASは自身の要求と結果、受信した状態変化、機器・保存・プロセス管理の異常を記録する。受信したGoal状態から原因や操作主体を推定しない。

## 保存先と形式

設定ファイルと同じ親フォルダーの`logs/<UTC開始日時>_<PID>/gigas.jsonl`へ、UTF-8のJSONを1行1件で保存する。開始日時は`20261117T093000Z`形式。同じ起動のログだけを回転させ、別プロセスの書込先を共有しない。UUIDや同名フォルダーへの連番付与は行わない。

共通項目は`timestamp`（UTC、ミリ秒、末尾Z）、`level`、`source`、`message`、`pid`。GIGASの診断イベントには`event`を付ける。関連する`connection_id`、`thread_id`、`turn_id`、`operation_id`、`reference`、`child_pid`などは取得できる場所で付け、欠けた値を推定しない。`pid`はGIGAS自身、`child_pid`は子プロセスを指す。例外や外部エラーの詳細はメッセージ、追加項目、トレースバックに保持する。

## 記録対象

INFOで起動・終了、設定の読み書きと適用要求、機器・Codexの接続、実行開始と終端、停止・再開などの操作要求と結果、Goalの状態変化を残す。失敗には警告・エラーの重要度を付ける。正常な毎入力・毎フレーム、応答の断片、Goalの利用量だけの更新は記録しない。会話本文・画像・正常なRPC本文を共通ログへ複製しない。

App Serverの標準エラー出力はJSONと非JSONの両方を取り込む。RPCエラー、ターン失敗の詳細も保存する。映像取得子プロセスは既存の64 KiB制御通知へ例外情報を付け、長いトレースバックは末尾6,000文字と省略表示を渡す。通常の画面用エラー文とは分ける。GUI・Pythonスレッド・サービスループの未捕捉例外も記録するが、OS強制終了やネイティブクラッシュの完全な捕捉は保証しない。

認証ファイルや環境変数一覧は収集しない。保存前に既知の認証項目、Bearer形式、GIGASが発行した接続トークンを除外する。保存失敗通知と未捕捉例外の標準エラー出力にも除外処理を適用する。未知の秘密情報を任意の文章から完全に除外する保証はなく、パスなどの診断情報は保持する。

## 容量と整理

1ファイル10 MiBを目安に回転し、現行と`.1`～`.9`の計10本を保持する。終了済みの起動フォルダーを開始日時順で直近10回分保持する。稼働中は別枠で、OSのファイルロックにより保護する。異常終了後にロックファイルが残っていても、OSロックが解放されていれば整理できる。

整理は起動時と正常終了時に行う。整理が競合した場合や削除に失敗した場合は見送り、次回に再試行する。管理対象名のログ・ロック以外があるフォルダーは削除しない。日数制限、圧縮、総バイト数による整理は行わない。終了済み約1,000 MiBに稼働中の分が加わる目安であり、巨大な単一レコードや削除失敗による超過がある。

## 保存の実行と失敗

標準loggingとpython-json-loggerを使う。発生元から`QueueHandler`、上限なしの`queue.SimpleQueue`、`QueueListener`を経由し、別スレッドの`RotatingFileHandler`へ渡す。ディスク停滞や大量の異常時にはキューのメモリ使用量が増え得る。

ログ保存の失敗でゲーム操作を停止しない。既存の通知欄へ保存できていないことと対象パスを通知し、同じ失敗の連続通知とログへの再帰を避ける。書き込み復旧後には`logging.recovered`を残す。失われたログの再構成や正確な欠落数は保証しない。

終了時は入力停止と機器・会話資源の解放を先に行い、その結果を記録してからログの投入を閉じて保存待ちを回収する。回収はGUIスレッド外で行う。強制終了時の末尾保存や、ディスク処理が戻らない場合の終了時間は保証しない。
