# 映像プレビュー

キャプチャーデバイスから映像を取得し、最新の画像をプレビューへ表示します。観測画像の保存、Codexへの画像送信、ゲーム操作はまだ提供しません。

## 設定

「設定…」を開くと、未接続なら機器一覧を非同期に取得します。「I/O」で機器の表示名・取得FPS・取得解像度を選び、「適用」を押します。取得中に開いた場合は既存の候補を使い、プレビューを継続します。識別子を手入力する必要はありません。表示FPS・プレビュー方式・ウィンドウサイズは「一般」で変更します。FPSの範囲と旧設定の扱いは[設定](settings.md)を参照してください。

「接続」→「映像」メニューでも、開いた際に一覧を取得して機器を選べます。取得中は既存候補を使います。選択すると設定画面と同じ保存・適用処理へ進みます。設定画面に未適用の編集がある場合はメニューからの選択を止めます。

## 接続と切断

機器欄は接続したい取得先です。設定を開いた時点では現在の取得先を選び、停止中は「未接続」になります。前回保存した実機は候補に残るので、接続するにはその機器を選んで「適用」を押します。保存機器が未検出でも別の機器へ自動変更しません。

取得先・取得FPS・取得解像度の変更を適用すると、必要な設定保存の成功後、旧取得の終了を確認してから新しい設定で接続します。最初の有効な画像を受け取るまで接続の成功とは扱いません。「未接続」を明示的に選んで適用すると停止し、保存済み機器も空にします。最初から「未接続」と表示されているだけでは、保存値を変更しません。

保存に失敗した場合は現在の映像と編集内容を維持します。保存後に接続だけ失敗した場合は設定画面を残し、値を変えずに「適用」で再試行できます。旧機器へ自動復帰しません。「OK」は必要な保存と映像反映が成功してから閉じ、「キャンセル」は未適用の編集だけを破棄します。

「接続」→「映像」の停止操作は一時停止で、保存済み機器を保持します。保存待ちでも使え、その保存後に予定していた未開始の接続も取り消します。設定画面の取得先は「未接続」へ戻り、他の編集は保持します。停止後は終了を確認してから一覧を更新します。設定ファイルの読込失敗中も、取得中の映像は停止できます。

起動・設定の再読込・アプリ終了時の未保存確認による保存だけでは自動接続しません。機器欄が「未接続」のまま表示設定やモデルを適用しても映像を開始しません。表示設定だけの変更は取得を開き直さず、共有画像も変えません。

機器一覧の更新と接続は同時に実行しません。失敗の理由は「表示」→「通知…」から再確認できます。通知を閉じても、終了未確認の状態を正常終了として扱いません。

ステータスバーの映像側には現在の機器名と接続状態、Codex側には実際の状態とモデルを表示します。映像欄とCodex欄の境界はドラッグでき、状態表示の位置も追従します。

「表示」→「映像情報…」では、接続に使った要求解像度・FPS、到着画像の寸法、機器報告FPS・実測FPS、取得方式、接続世代・連番、終了確認状態を確認できます。代替方式を試した場合は先行試行の診断も表示します。要求が60 FPSでも実際の到着頻度が60になるとは限りません。各値の定義は[取得API](video-api.md)を参照してください。

映像情報は開いた時点の値を保持し、選択・コピー中に書き換わりません。最新の値に更新するには、同じメニューをもう一度選びます。映像情報を開閉しても、機器一覧の更新・接続・切断や失敗通知は発生しません。

## 取得解像度

| 選択 | 機器への要求 |
|---|---|
| 自動 | 幅・高さを指定せず、ドライバーが返す画像を使う |
| HD | 1280×720 |
| FullHD（既定） | 1920×1080 |
| WQHD | 2560×1440 |
| 4K | 3840×2160 |

固定値は機器への要求であり、実際に届く画像の寸法を保証しません。要求と異なる有効な画像が届いた場合も、実寸法と画素を保って共有します。指定寸法になるようにアプリで黒帯を付けたり、拡大・縮小したりはしません。「自動」も最大・最適解像度を探索する機能ではありません。

受け入れる画像は幅16〜3840、高さ16〜2160の3チャンネルBGR・uint8です。上限を超える場合はエラーにし、黙って縮小しません。一度取得を開始した後に画像寸法が変化した場合も停止します。信号が変わった場合は新たに接続してください。この寸法はOpenCVから受け取った画像の値であり、HDMI原信号の解像度を保証する情報ではありません。

## 取得方式と機器識別

取得層では、OSとOpenCVで利用できる方式から候補を選びます。

| OS | 優先する方式 | 代替候補 |
|---|---|---|
| Windows | DirectShow | 同じ識別子に一意に一致するMSMFの機器 |
| Linux | V4L2 | 安定した別名から同じデバイスノードへ解決できるGStreamerの機器 |
| macOS | AVFoundation | なし |

保存した識別子に一意に対応する候補だけを、取得開始前に順に試します。表示名・番号・VID/PIDだけで別方式の機器を同一と推測しません。失敗した候補の正常解放とプロセス終了を確認するまで次へ進まず、停止要求や終了未確認で代替試行を中止します。取得開始後の自動再接続やダミー映像への切替はありません。

識別子にはWindowsの機器パス、Linuxの`by-id`・`by-path`の別名、macOSの`uniqueID`を使います。識別子が得られない機器や一意に照合できない候補は自動選択しません。保存済みのWindows識別子を別OSの機器名や番号へ読み替えることもありません。

これはカメラ取得層の方式選択です。アプリ全体のLinux・macOS対応を保証するものではありません。既定設定パスはWindowsの`LOCALAPPDATA`を使います。他OSの起動、機器権限、macOSでの機器とOpenCV番号の対応は実機未検証です。4K原信号や全機器の対応モードも確認済みとはしません。

## 表示サイズ

「表示」メニュー、または設定の「一般」タブから選びます。どちらも同じ設定を保存し、成功後に表示を変更します。設定に未適用の編集がある場合や処理中は、メニューでの変更を停止します。

| 選択 | ウィンドウの希望寸法 | プレビューの希望寸法 |
|---|---|---|
| HD | 1280×720 | 768×432 |
| FullHD（既定） | 1920×1080 | 1280×720 |
| WQHD | 2560×1440 | 1600×900 |
| 4K | 3840×2160 | 2560×1440 |

画面の作業領域に合わせて両方を同じ倍率で縮めます。操作部品に必要な領域がある場合、実際のプレビュー枠は残りの領域へさらに縮小します。表示サイズを変えても取得画像の寸法や接続世代は変わりません。

## 表示の契約

「一般」の「プレビュー方式」で表示時の比率調整を選びます。「レターボックス」は画像全体の縦横比を保って枠へ収め、残る領域に黒い余白を付けます。「ストレッチ」は縦横それぞれを枠へ合わせます。例えば4:3の画像を16:9の枠へ表示すると、レターボックスでは左右に黒帯ができ、ストレッチでは横へ広がります。画像の切り抜きや、入力画像に既に含まれる黒帯の除去は行いません。

プレビューは取得した最新1枚を表示します。表示が遅れた場合は途中の画像を省き、最新画像へ進みます。表示FPSは更新頻度の上限です。切断・取得失敗時は表示FPSの次回更新を待たずに画像を消去します。

表示のための拡縮は、取得解像度が「自動」の場合も取得画像を書き換えません。取得時刻はPC側で画像を受け取った時刻であり、ゲーム画面が生成された時刻やキャプチャーデバイス内部の滞留時間を保証しません。観測用の縮小・切り抜き・保存・MCP応答は後続のU04で扱い、現在のプレビュー設定を観測画像の設定としては扱いません。

## 終了

アプリの終了時は映像取得も停止し、機器を所有する処理の終了と資源の解放を確認します。正常終了の待機期限を超えた場合は取得プロセスを強制終了します。強制終了と機器APIによる正常解放は、取得サービスの状態で区別します。

「終了未確認」は、取得プロセスの終了、またはアプリ側の共有メモリや通信資源の解放を確認できていない状態です。この状態ではアプリを正常終了した扱いにせず、再接続も行いません。
