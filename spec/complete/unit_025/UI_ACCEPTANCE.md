# UI改善の画面・実機検証

状態: 対象範囲の画面・実機受入を完了。個々の確認結果を記録し、未実施項目を分ける。[実装仕様](UI_UX_REFINEMENT.md)の受入記録。

## 実機の映像適用

2026-11-11、`2ed623d`で実施。Windows、Python 3.12.10、Qt 6.12.0。実キャプチャーはLive Gamer 4K 2.1系（VID07CA/PID0575、DirectShow表示名`USB Video Device`）。機器パスは今回の自動列挙から得た値を使用した。接続中のゲーム画面を受信し、描画画像でGAME FREAKロゴを目視した。

`uv run python -X utf8 tmp/uiux-refinement/hardware_apply.py`により実サービス・実Qtの設定ウィジェットを操作した。物理機器を使っているが、Qt描画はoffscreenであり、Windowsのネイティブ画面操作とは区別する。描画用プロセスだけMeiryo UI 9ptを指定し、製品フォントは変更していない。設定ファイルも一時ディレクトリ内へ隔離した。

| 操作・観測 | 結果 |
|---|---|
| 空の設定→設定画面を開く | 一覧を自動取得し、機器の表示名で選択できた |
| 機器選択→適用 | 保存後に接続し、1920×1080の最初のフレームを取得した |
| 取得中に設定を閉じて再表示 | 再列挙・再接続せず映像を継続した |
| 表示FPS 30→15、表示サイズHD→FullHDを適用 | 取得世代1を維持。約6秒間で連番363、プレビュー121更新。別読み手が保持する画像も不変 |
| 取得FPS 60→30→60を適用 | 世代1→2→3。各旧世代の正常解放を確認した後、新世代を接続した |
| 設定内で切断 | 映像を無効化し、正常解放後に一覧を1回更新した |
| 保存済み機器へ再接続 | 世代4の最初のフレームと継続更新を確認した |
| アプリ終了 | 検証全体約29.94秒。終了時は取得サービス停止、設定ワーカー/Codexサービスの終了、子プロセス残存なし、`cleanup=graceful`を確認した |

30 FPS要求時の機器報告は30.00003 FPS、約3秒の観測では実測28.69 FPS。60 FPS要求時の報告は60.00024 FPS、実測58.69 FPSだった。要求値と機器報告と実測値を区別し、短時間の結果を長時間性能の保証にはしない。20ms間隔の観測で子プロセスは最大1つだった。

この確認で、独立した読み手が保持する過去フレームはプレビューを停止させなかった。U04のMCP接続・画像保存や、U05のゲーム入力を実装・検証したことは意味しない。

## 通知の描画

T07の通知描画は実施済み。模擬イベントを実Qtへ投入し、Meiryo UI 9pt、作業領域800×600と1920×1080で通知・詳細・長い終了待ちの計6画面を確認した。外枠はそれぞれ800×451と1916×1080を維持。小画面で現在状態の幅67px、モデル名201px、中断80×24pxを確保し、長い値は省略、診断全文は専用の詳細領域で選択できた。コピー中の新着通知で本文が変わらないことは回帰試験でも確認した。主画面に残る旧設定行・接続ボタンはT08で変更するため、これを最終配置の受入とは扱わない。

## メニューの描画

T08では合成画像・模擬Codexイベントを使い、主画面と開いた映像メニューをHD／FullHD相当で描画した。外枠800×451、1916×1080を維持。旧設定ボタン行・映像上部の操作と状態がなく、メニュー・ステータスバーへ移ったことを確認した。長い同名候補と`&`を含むメニューは353×172pxへ収まり、省略しても末尾の(1)/(2)、保存済みの選択印を判読できた。これは合成描画の結果であり、機器名や画像を実機の観測結果とは扱わない。

T10完了版へT13の承認配置修正を加えたコードで、主画面、メニュー、設定3タブ、長い質問・選択肢、承認、通知の34画面を再描画した。作業領域800×600／1920×1080を模擬し、外枠は800×451／1916×1080。合成映像・模擬イベントを使い、実キャプチャーやCodexサービスは開始していない。初回の描画で承認ボタンの横方向の欠けを発見し、T13の回帰試験と縦配置へ反映した。

HDの質問・承認欄は258×191px、通知後の承認欄は258×153pxで、いずれも横スクロール0。承認は縦スクロールで3ボタン全体に到達する。設定3タブは外枠564×444px、通知詳細は624×424pxに収まる。長いモデル名・機器名は省略し、機器一覧の同名番号は残る。下書きの保持、質問の初期未選択、失効カードの折り畳み、詳細の文字選択中の本文保持も確認した。

代表画像は[主画面](assets/hd-main.png)、[映像設定](assets/hd-settings-video.png)、[未対応の既存認証値](assets/hd-settings-agent-unsupported.png)、[質問](assets/hd-question-top.png)、[承認操作](assets/hd-approval-actions.png)、[通知詳細](assets/hd-notification-details.png)。Meiryo UI 16ptのFusion／Windowsスタイルでも追加4画面を確認し、横スクロールなしで判断ボタンへ到達した。[16ptの承認](assets/hd-16pt-windows-approval-actions.png)。フォント指定は描画プロセスだけで、製品設定を変えていない。

## Windowsネイティブ画面と実機

2026-11-11、T10実装後（`c6159c2`の製品コード）にcomputer-useで実施した。Windows、Python 3.12.10、Qt 6.12.0、devicePixelRatio=1.5。設定・認証情報は検証用の別TOMLへ隔離し、Codex接続やゲーム入力を開始していない。`uv run python -X utf8 tmp/uiux-refinement/native_acceptance.py`で起動し、画面のクリック・キー操作で確認した。

| 操作 | 確認結果 |
|---|---|
| `Ctrl+,`で設定を開く | 初回に検索中→取得済みとなり、更新ボタンを押さずに表示名の候補を選べた |
| `USB Video Device`を選択して適用 | Live Gamer 4K 2.1のファイアレッドのタイトル・GAME FREAKロゴを確認。1920×1080取得の文字と縦横比を判読できた |
| 設定を閉じて映像メニューを開く | 映像を継続し、保存済み選択印・切断操作・機器一覧を確認。主画面の映像欄にはFPS・機器名・状態を重ねず、機器名と状態はステータスバーに表示 |
| メニューで切断→設定へ戻る | 画像を消去、正常解放後に一覧更新。保存済みの表示名を維持し、設定内の接続が有効になった |
| 設定から再接続→ファイルメニューで終了 | 新世代で実映像を再取得し、表示中の終了で全ワーカー・取得プロセスを回収した |

取得世代1と2のプレビュー更新は2037回・661回。約226秒の検証中、別の読み手が保持したフレームは変化せず、最終`cleanup=graceful`、取得サービス停止、設定ワーカー・Codexサービス停止、子プロセス残存なし。主画面1280×720論理pxで確認した。[状態遷移の記録](assets/native-ready.json)には機器パスや画像は含めていない。

不正TOMLを別ファイルに用意した`--broken`起動でも、実際の読込エラーを確認した。非モーダルの通知から説明と診断を開き、診断全文を選択できた。詳細を開いたまま`Ctrl+,`で設定を操作でき、編集・適用は無効、再読込は有効だった。詳細とバナーを閉じた後、ステータスバーの「通知」から同じ失敗を再表示できた。詳細を開いたまま主画面を閉じ、全ウィンドウとワーカーが終了した。[終了記録](assets/native-broken.json)。コピー内容の検証は自動試験で行い、このネイティブ確認では選択表示までを確認した。

## 未検証・対象外

実機の物理抜去、HDMI信号断、長時間運転、複数モニター間のDPI移動、実IMEの変換・確定、スクリーンリーダーは未検証。150%表示を1環境で確認したことを全DPI対応の根拠にはしない。機器切替の失敗・終了未確認などは自動試験の制御した境界で検証しており、物理機器で同じ障害を発生させたわけではない。実Codexへの回答・承認送信は今回再接続せず、模擬通信とQtの結合試験で確認した。U04の保存・MCP、U05のゲーム入力、U06のAPIキー認証・モデル候補は対象外である。
