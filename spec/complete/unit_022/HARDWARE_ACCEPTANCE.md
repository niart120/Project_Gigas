# U03 Windows実機受入記録

2026-11-11、製品コードを`f612734`（GUIの時計修正は`69b2660`）で固定して確認した。調査時の黒・青画像のプローブとは別の、製品の`ApplicationShell`・`CaptureService`・`VideoView`を通した受入である。

## 条件と手順

Windows x64、Python 3.12.10、Qt / PySide6 6.12.0。OpenCV-headless 4.14.0.94、NumPy 2.5.4、cv2-enumerate-cameras 1.4.0、DirectShowを使用した。ユーザーが映像出力を準備したLive Gamer 4K 2.1系を対象とし、Windowsの列挙名は`USB Video Device`、VID/PIDは`07CA/0575`だった。

```text
\\?\usb#vid_07ca&pid_0575&mi_00#b&367461cf&0&0000#{65e8773d-8f56-11d0-a3b9-00a0c9223196}\global
```

要求は1920×1080、取得60 FPS、表示上限30 FPS。FourCCを上書きせず機器既定値を使った。通常のsandboxでは列挙できてもopenに失敗したため、実機利用を許可されたプロセスで実行した。設定は一時的な独立TOMLへ保存し、普段の設定を変更していない。

GUIで「設定…」→「一覧更新」を操作し、保存済みのパスが`2: USB Video Device`へ解決されることを確認した。その後「接続」→実映像の継続表示→「切断」→同じ機器へ「接続」→映像表示中にウィンドウを閉じた。Codex接続・ゲーム入力は行っていない。

## 確認済みの結果

ポケットモンスター ファイアレッドのタイトルと動く導入映像を両接続で確認した。タイトルの日本語、`PUSH START BUTTON`、`GAMEFREAK`を判読できた。1920×1080の取得画像を縦横比を維持して表示し、元の画像内の黒い余白と、表示領域に追加される余白を区別した。GUIに説明本文はなく、接続・切断、設定の操作部品と短い状態・数値を確認した。

| 操作 | 状態遷移と結果 |
|---|---|
| 一覧更新 | `enumerating → stopping → idle`、`cleanup=graceful`。保存パスと表示名の対応を確認 |
| 1回目の接続 | 世代1、実寸法1920×1080。要求から最初のstreaming観測まで約3.34秒。停止時の取得実測59.81 FPS |
| 切断 | 表示画像を消去。`stopping → idle`を約94 ms間隔で観測し、`cleanup=graceful` |
| 再接続 | 世代2、実寸法1920×1080。最初の画像は連番1。要求からstreamingまで約3.23秒。終了時の取得実測59.08 FPS |
| 表示中の終了 | `stopping → closed`を約109 ms間隔で観測し、`cleanup=graceful`。ウィンドウ消失、監視スレッド停止、`multiprocessing.active_children()`は空 |

FPSのAPI報告値は両接続とも60.000240000960005。上記の取得実測は受信した連番とホストの単調時計から求めた値で、要求値・API報告値とは区別する。停止時間は20 msの観測タイマーによる状態遷移の差であり、機器のreleaseだけの精密計測ではない。最終実行の標準エラー出力は空だった。

表示の計測は`VideoView.set_frame`に届く新しい世代・連番を数え、`perf_counter()`で期間を計った。1回目は約22.2秒、2回目は約12.2秒の表示である。実画面の走査・提示完了を計測したものではない。

| 接続世代 | 表示へ渡した画像数 | 実測更新頻度 | ホスト取得完了から表示へ渡すまでの中央値 / p95 / 最大 |
|---|---:|---:|---|
| 1 | 584 | 26.33 FPS | 16 / 31 / 32 ms |
| 2 | 293 | 24.04 FPS | 16 / 31 / 78 ms |

ホスト時刻差にはPython 3.12の`monotonic_ns`を使ったため、約15.625 msの時計分解能を含む。GUI側の20 ms観測タイマーはp95が32 ms、最大140 msだった。表示上限30 FPSに対し一定30 FPSを保証する結果ではない。表示判定を`perf_counter()`へ変えたP4aの前は約15.6 FPSだったため、この環境で改善を確認した。

## 未検証と適用範囲

- 物理ケーブルの抜去、HDMI信号消失、実ドライバの固着中の強制終了は実施していない。読込失敗・固着・異常死・期限超過・強制終了・終了未確認は、別の実spawn結合試験で故障を注入して確認した。
- 機器内部のバッファ滞留、映像生成から画面表示までの光学的遅延、入力後の反映遅延は未計測。ホスト取得時刻をこれらの保証に使わない。入力との結合はU05で確認する。
- この最終受入は上記1機器・1モード・短時間で行った。Elite Go GC313ProとGV-USB2はM0プローブのみ。他の解像度・FPS、複数機器同時利用、長時間連続運転、表示倍率・複数モニターの網羅確認は含まない。
- 保存画像・MCP配送はU04、ゲーム入力・即時停止はU05であり、この試験の診断画像・計測ログを製品の保存機能とは扱わない。
