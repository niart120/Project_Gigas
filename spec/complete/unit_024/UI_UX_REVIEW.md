## 5. NyXの照合と採否

## 6. 改善設計案と適用境界

### 6.1 主画面

| 場所 | 提案する役割 |
|---|---|
| ファイルメニュー | 設定…、終了。右上の独立した設定ボタンの行を除く |
| 接続メニュー | 映像の機器選択・更新・切断、Codexの接続・切断・ログイン。映像の候補は表示名。設定ダイアログと同じ選択・適用状態を参照する |
| 表示メニュー | 既存の4プリセットを排他選択。NyX同様、不要な深い階層を作らない |
| 中央 | 映像プレビューと会話。会話の送信・中断は操作対象の近くに残す。要求中は質問・承認を読む領域を確保する |
| ステータスバー | 映像の状態＋現在取得中の機器名を常設。Codexの接続・実行状態と区別する。終了待ち・エラーの詳細への入口を確保する |

ステータスバーを全文診断の置き場所にはしない。短い状態、長い機器名の省略、詳細の参照を分け、幅を超えて主画面を拡大させない。設定の保存状態と映像状態が同じラベルを上書きしない構成にする。GUIへ説明本文や説明用ツールチップを加えず、操作手順はdocsへ書く。

### 6.2 設定から映像を切り替える

設定を開く→候補を非同期取得→機器を選ぶ→「適用」で保存と映像接続の反映、という導線を候補とする。コンボ選択だけで保存・接続を始めない。設定画面内に現在の接続状態と切断操作も置き、主画面へ往復しなくてよい形にする。

保存成功と接続成功は別結果として扱う。例: A取得中にBを適用し、保存成功後にBの接続が失敗した場合は「保存済み／接続失敗」と現在の取得状態が分かるようにする。失敗時にAへ自動復帰するか、停止状態で再試行を待つかは実装仕様の着手時に決定する。無断の自動接続や偽の成功表示を設けない。

現在の列挙APIは取得中に列挙できない。このため「常に再列挙すればよい」だけでは解決しない。取得中は既存候補を表示してプレビューを継続する。接続したままの機器追加検出を別の列挙経路で実現するか、明示的な切断後に更新するかは、次の調査・設計で決める。ダイアログを開くだけで現在の映像を切断しないことを受入条件にする。

映像機器・取得FPSの適用と、表示FPS・表示サイズの適用を分ける。後者だけの変更で映像を再接続しない。モデル変更・APIキー・ゲーム入力の反映をこの処理へ便乗して実装済みとは扱わない。
