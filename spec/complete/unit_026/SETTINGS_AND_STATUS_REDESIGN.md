## 4. 画面構成

### 設定

タブは「一般」「I/O」「Codex」の3つとする。一般は設定ファイルの読み込み先と「表示」（ウィンドウサイズ、プレビュー方式、表示FPS）、I/Oは「映像入力」（機器、取得FPS、取得解像度）と「コントローラー」（既存シリアル設定）、Codexは現在のモデル・エフォート・認証設定を置く。表示FPSとレターボックスは表示だけを変えるため一般へ分類する。Codex設定の適用を接続中モデルの変更とは扱わない。

「機器一覧」「映像／接続」の独立した行見出しと、正常時の取得済み・変更なし・保存済みは除く。機器コンボと一覧更新を近接配置する。第5節の契約に従い、接続／切断の常設ボタンを設けず、選択と適用で開始・切替・停止する。

未適用の機器選択と実際の取得先が異なる間だけ、機器行の近くに現在の取得先を表示する。コンボの選択が接続済みだと誤解させないためであり、通常時の同じ名前・状態の重複は復活させない。

一覧の初回自動取得と表示名選択は維持する。検索中は更新ボタン付近だけに表示し、未確認・未検出の保存機器はコンボ内で識別する。列挙に失敗しても既存候補と未保存選択を失わない。「取得済み」の成功行は出さない。

適用ボタンの有効条件は、設定の編集差分と、実行状態への反映要求を区別する。保存後に接続だけ失敗した場合、編集差分がないことを理由に再試行できなくしてはいけない。再読込後の保存値と実取得設定の差も扱う。

旧入力タブはI/Oへ統合し、シリアル値の編集を維持する。`serial_port`を含む保存済み値・未知項目は、ほかの項目のOK／適用で変更せず保持する。シリアル値の編集は保存機能に限り、接続成功の表示や未実装の接続ボタンは追加しない。U05でコントローラーの機器候補・接続を実装する際にこのグループを拡張する。

設定ファイルの読み込み先は、全タブ共通の上部から一般へ移す。「設定ファイル」の1行で現在のパスを読取り・コピーできるようにする。ファイル選択・保存先変更は今回追加しない。「ファイル」メニューへ再読込と場所を開く操作を置き、下部の再読込ボタンは外す。機器一覧の更新とは別操作として維持する。再読込は明示操作だけとし、編集中なら破棄確認、失敗時は入力を保持して保存を禁止する。読込エラー中もこの復旧経路とパスへ到達できる。

設計時の[一般タブ旧案](assets/settings-proposal.png)と[I/Oタブ旧案](assets/io-proposal.png)は、配置の検討に使った静止モックである。サービス・設定保存・機器操作を伴わず、製品の画面や受入検証の証拠ではない。画像内の項目名・配置は旧案として保存し、実装契約は本節と第5・6節の本文を正とする。

### 主画面と通知

ステータスバーは映像列・Codex列に対応する2領域へ分け、各領域内は左寄せにする。境界は画面の半分で固定せず、映像／会話のsplitter移動とウィンドウ幅へ追従する。左に映像の短い状態と現在取得中の表示名、右にCodexの状態と実モデル・エフォートを置く。会話上部の同じ状態・モデル表示は除き、「Codex」の見出しは残す。現在取得中の名前を、未適用の選択や保存済み選択と取り違えない。

短い状態を優先して残し、長い機器名・モデル名だけを省略する。全文は識別値のツールチップ等から参照できる。FPS・取得寸法・準備完了などの冗長な常設項目は追加しない。

「表示」→「映像情報…」から、要求解像度・FPS、到着寸法、機器報告・実測FPS、取得方式、試行診断、世代・連番、終了確認状態を参照できる。本文は開いた時点の値を保持し、再度メニューを選んだ時に更新する。コピー中の表示を自動更新せず、開閉によって取得操作や失敗通知を発生させない。

「通知」ボタンはステータスバーから外し、「表示」→「通知…」へ移す。新着エラーは現在の非モーダルバナーを使い、そこから詳細も開ける。通知を閉じても履歴を残し、履歴を未解決件数や現在の異常として表示しない。通知なしの平常時に無効なボタンを置かない。

ステータスバーの終了取消しボタンも外す。取消し可能な終了待ちの間だけ、主画面の非モーダルな処理表示へ状態と終了取消しを出す。終了確定後は取消しを表示せず、終了未確認は説明と詳細を表示する。設定保存自体を中断したと偽らず、取り消した接続予定やCodexターンを自動再開しない。通知履歴を終了待ち表示で消さない。

[主画面の配置旧案](assets/status-proposal.png)も設計時の合成表示であり、現在の製品画面や実機観測を表さない。

## 5. 未接続を含む選択と適用の契約

機器コンボの先頭に「未接続」を置き、その下に実機の表示名を並べる。「未接続」は機器を使わない要求であり、仮想機器ではない。黒画像を生成せず、停止後は現在有効な共有フレームを失効させる。設定で未接続を明示選択して適用するか、接続メニューで未接続を選ぶと、保存機器も空にする。メニューの「映像を停止」は一時停止として保存機器を保持する。初期表示が未接続であるだけでは機器設定を変更せず、一般設定の変更で消去しない。

接続／切断は別の常設ボタンにせず、「何へ切り替えるか」を選んで適用する。追加の使用チェックボックスは同じ選択を二重化するため置かない。機器一覧の更新は候補の再取得だけであり、接続状態を変えない。

| 選択と操作 | 結果 | 機器の記憶 |
|---|---|---|
| 未接続から実機Aを選択→適用 | 保存成功後にAを開始 | Aを保存 |
| 取得中のAから実機Bを選択→適用 | 保存→Aの解放確認→Bの最初のフレーム | Bを保存 |
| 設定で未接続を明示選択→適用、または接続メニューで未接続を選択 | 保存後に取得を停止し、解放完了を待つ | 保存機器を空にする |
| メニューの「映像を停止」 | 取得を停止し、未開始の接続予定を取り消す | 変更しない |
| 初期表示の未接続を編集せず、一般・Codexの設定を適用 | 設定だけを反映し、機器を開かない | 変更しない |
| 接続失敗後に同じ実機のまま適用 | 保存済みなら再保存せず接続を再試行 | 変更しない |
| 取得中の同じ実機に表示設定だけを適用（取得条件に未反映差分なし） | 表示だけを反映し、取得は継続 | 変更しない |

起動時は自動接続しない。停止中に設定画面を開くと「未接続」を選択し、記憶している実機は候補として残す。列挙前・不在の場合も既存の未確認／未検出表示で保持する。保存機器が存在するだけでは開始要求を作らない。未接続から前回の機器を選ぶ操作も実行状態の差分として扱うため、TOMLに変更がなくても適用できる。

終了未確認は未接続成功と区別する。取得フラグが落ちただけでは機器の解放を確認したことにせず、終了未確認の状態・診断・新接続禁止を維持する。

保存設定、実際の取得状態、ダイアログの適用先要求を別に持つ。「未接続」はその要求の値であり、DevicePath用の空文字や特殊文字列としてバックエンドへ渡さない。現在の取得先と要求が異なるときだけ現在値を補助表示する。保存成功で要求を消さず、接続失敗後も再試行できる。キャンセルして開き直した場合は実行状態から要求を作り直す。

開いた時と明示的な再読込の成功時には、取得先の要求を現在の実行状態から初期化する。再読込した機器Bと取得中の機器Aが異なっても、再読込だけではAを止めずBを開始しない。保存済みの機器は実機または未接続を明示選択した場合に更新し、一般タブの変更等でAを保存値Bへ無断で書き戻さない。一覧更新・前面化・保存完了は未適用の要求を上書きしない。保存値と実取得条件が異なる場合、次の明示的な適用で現在の要求先と取得条件を反映する。

同じ機器でも、再読込した要求FPS・要求解像度が現在の取得世代に適用した要求値と違えば反映待ちである。比較するのは要求値同士であり、要求FullHDに対して実到着720pを受け入れた場合も同じ要求値は適用済みとする。機器報告値や実到着値との差で適用を繰り返さない。設定の近くに未反映差分がある間だけその状態を示し、適用では全タブの差分を反映する。現在開いているタブだけを適用する契約にはしない。

主画面の接続メニューは同じ機器選択を行う近道とし、ダイアログ側の必須操作にしない。機器のチェックは現在の取得先を表し、停止中は未接続とする。未接続の選択も設定解除を伴う共通の適用処理を通す。未保存の設定編集中はメニューからの選択を拒否する。

取得中または開始待ちには「映像を停止」を残し、適用待ちの開始要求も取り消せる。これは処理中に待たず機器を解放する操作であり、保存自体の取消しではない。この一時停止ではダイアログの取得先要求も未接続へ同期し、後の別設定の適用で取り消した開始要求を復活させない。保存機器と他の未適用設定は保持し、停止操作で無断保存・破棄しない。

### 共通のボタン契約

| 操作・状態 | 期待する動作 |
|---|---|
| OK | 適用と同じ保存・必要な映像反映を行い、成功後に閉じる。差分がなければ閉じるだけで、不要な再保存・再接続はしない |
| 適用 | 保存と必要な映像反映を行い、画面を開いたままにする |
| キャンセル／×／Esc | 最後に保存が成功した値以降の未適用編集を破棄して閉じる。既に適用した保存・表示・接続を巻き戻さない |
| 保存失敗 | 画面と編集を残す。旧映像を維持し、新接続を始めない |
| 保存成功・新接続失敗 | 保存値と画面を残し、失敗を知らせる。旧機器へ自動復帰せず、編集差分なしでも明示再試行できる |
| 旧取得の終了未確認 | 新接続を禁止し、終了未確認の理由と診断へ到達できる |

OKが待つ成功は、必要な保存、旧取得の終了確認、新世代の最初のフレームまでを指す。表示だけの変更で取得を再接続しない。手動切断、保存・接続・旧取得終了の失敗、アプリ終了要求ではOKの自動クローズ予定も破棄する。後の再試行成功や終了取消しで古いOK予定を復活させない。

非同期の保存・反映中は、下部3ボタンと×／Escによる設定ダイアログ終了を一時無効にする。処理中であることはその間だけ短く表示する。開始済み保存を取り消せるように見せる別の取消し操作は増やさない。その間もモデルレスを維持し、映像の切断と主画面のCodex中断、アプリ終了は操作できる。アプリ終了による未開始接続の取消しと未保存確認は維持する。

未接続からの保存待ちに接続予定があれば停止要求で取り消せるようにし、終了確認中に再接続しない。未適用の選択と旧保存機器を取り違えず、既存取得の停止は許可する。

ボタンは標準の役割で構成し、順序はQtのプラットフォーム配置へ委ねる。[QDialogButtonBox](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QDialogButtonBox.html)はOKをAccept、CancelをReject、ApplyをApplyとして配置する。添付NyXの順はOK・キャンセル・適用であり、設計時のモックでもこの順を用いた。[QStatusBar](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QStatusBar.html)自体は操作部品も許容するが、本仕様では状態表示に役割を絞る。

## 6. 取得・プレビュー・観測の分離と取得方式

### NyXで確認した範囲

NyXの[カメラ取得](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/framework/core/hardware/camera_capture.py)は1920×1080を要求し、機器報告値が一致しなければ720×480を試す。[FrameTransformer](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/framework/core/hardware/frame_transform.py)はリサイズせず、16:9になる黒キャンバスの中央へ元画像を置く。[取得口](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/framework/core/io/device_factories.py)がこの変換器で包まれ、読み出し時に変換される。[プレビュー](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/gui/panes/preview_pane.py)では別途16:9の表示寸法へリサイズするため、黒帯なしの場合は表示段階で引き延ばす。

NyXの[4段階プリセット](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/gui/layout.py)はウィンドウとプレビューの寸法であり、共有取得画像を自動／4K等へ変換する設定ではない。変換設定の分離・中央の黒帯・縮小と拡大の補間の使い分けは参考にする。固定16:9キャンバス、DPRによる寸法、読み手ごとの変換、保存画像の固定寸法はそのまま採用しない。

### 取得解像度とプレビューの契約

I/Oの映像入力には「取得解像度」を置く。一般タブに「プレビュー方式」の独立した行を設け、「レターボックス」「ストレッチ」をコンボで選ぶ。ウィンドウサイズはアプリ全体の大きさなので、その横にチェックボックスは置かない。取得画像を共通の指定寸法へソフトウェアで変換する前案は取り下げ、機器への要求と表示時の加工を分ける。

| 取得解像度 | 機器への要求 |
|---|---|
| 自動 | 幅・高さを指定せず、ドライバーが返した画像を使う |
| 4K | 3840×2160 |
| WQHD | 2560×1440 |
| FullHD | 1920×1080 |
| HD | 1280×720 |

固定値は機器へ要求する解像度であり、実到着画像の寸法を保証しない。要求と異なる有効な画像が届いた場合も、その実寸法と画素を保って共有し、要求との差を診断へ記録する。アプリ側の黒帯追加・引き延ばし・縮小で指定寸法に見せかけない。自動は最大・最適解像度の探索ではない。FPSの要求と実到着頻度の区別も維持する。

「レターボックス」を選ぶと、プレビュー枠に画像全体が収まる倍率で表示し、余白を黒にする。クロップしない。「ストレッチ」では縦横それぞれを表示枠へ合わせる。例えば4:3の画像を16:9のプレビュー枠へ出すと、前者は左右に黒帯、後者は枠全体へ引き延ばされる。共有Frameの画素・寸法には影響しない。取得解像度が自動でも、この選択は有効である。

入力に既に含まれている黒帯の検出・除去、画像内容からのゲーム領域検出は対象外とする。

既定は取得解像度FullHDと、プレビューのレターボックス有効とする。変更前の1920×1080要求と比率を保つ表示を維持する。保存項目は`capture.resolution`（`auto` / `four_k` / `wqhd` / `full_hd` / `hd`）と`gui.preview_letterbox`（真偽値）とする。前案の`capture.output_size` / `capture.fit_mode`は採用していない。既存の未知キー`capture.width` / `capture.height`は再解釈せず保持する。不正値は設定エラーとし、項目省略には上記の既定値を使う。

### 取得と共有の境界

取得プロセスで有効な画素・実寸法を検査し、不変Frameを1回作って共有する。機器から到着したBGR画像の解像度と比率を保持し、表示都合の変換を加えない。プレビューと後続の観測がこの基準画像を独立して読み、読み手ごとに機器を開かない。取得直後の時刻・連番を保持する。

「同じ画像を読む」は最終的な表示・観測画像の寸法や内容まで一致させる意味ではない。プレビューは表示枠へ拡縮する。U04の観測は取得したFrameから必要に応じて縮小・切り抜き等の派生画像を作れる境界とする。観測側の設定や要求で共通の取得設定を変更したり、再接続したりせず、取得ロックとGUIスレッドの外で処理する。確定した派生画像を保存とMCP応答で共通に使い、取得世代・連番・時刻と変換内容を追跡できるようにする。

表示領域の小ささを理由に取得画像まで縮小しない。観測に十分な情報量を保てる取得解像度を選び、U04の観測で必要な大きさへ加工する。機器が返さなかった細部は後段で復元できない。U04で観測加工の公開方法・上限・座標系・同時処理量を設計し、実負荷で応答性を検証する。[U04親仕様](../../wip/unit_009/RECORDED_OBSERVATION.md)へ設計事項を引き継ぎ、今回そのMCP機能を実装済みとはしない。

Frameの幅・高さは実際の共有画素と一致させる。取得層で表示用の黒帯を追加しないため、Frameに表示上の画像領域を持ち込まない。これはHDMI原信号の寸法を保証する情報ではない。サイズ・FPSを主画面に常設せず、第4節の映像情報から要求値と実到着値を確認する。

[取得処理](../../../src/gigas/game_io/capture/backend.py)は要求と異なる有効な寸法も受け入れる。[共有メモリ](../../../src/gigas/game_io/capture/_process.py)は自動・固定要求とも上限3840×2160×3＝24,883,200bytesの画素領域1枠を確保し、ヘッダーに実寸法を持つ。実寸法分だけを転送し、画素とメタデータを同じ短いロックで読み書きする。固定要求でも別寸法が到着するため最大容量を共通にする。初回フレーム後のメモリ確保交渉は停止経路を増やすため採用しない。上限超過は失敗として通知し、黙って縮小しない。変更前の要求寸法との一致検査と要求寸法での事前確保は、この契約に置き換えた。

到着画像の受入範囲は幅16〜3840、高さ16〜2160、uint8の3チャンネルBGRとする。総容量以内でも7680×1080等は対象外とし、各辺を検査する。

同一世代内では最初に確定した到着寸法を維持し、途中の寸法変化は明示的な取得エラーとする。信号変更に自動追従する機能は今回追加しない。失敗後の新しい明示接続は新しい世代で行う。取得解像度・取得FPSを適用するときも旧取得の終了を確認し、新世代の最初のフレームから切り替える。旧画素を新設定の画像として表示せず、取得失敗後に旧フレームを現在画像として再公開しない。ウィンドウサイズ・表示FPS・レターボックスの変更ではこの切替をせず、共有画像も変えない。

4Kの実到着頻度・転送量、同時のプレビューと独立読み手、停止応答を受入対象とし、実行した条件と結果を製品検証の記録に残す。MCP接続・観測保存・観測専用加工の完成や実負荷の検証はU04のままである。

### OS別の取得方式とフォールバック

NyXの[機器列挙](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/framework/core/hardware/device_discovery.py)はWindowsでDirectShow、LinuxでV4L2、macOSでOpenCV既定の番号探索を使う。物理カメラでDirectShow失敗から別APIへ進む処理はなく、初期化失敗時の代替は許可された場合のダミーである。[ウィンドウ取得](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/framework/core/hardware/window_capture.py)のWGC→MSSは別の取得元の処理である。OS別に方式を選ぶ構成を参考にし、物理カメラのAPI間フォールバックはGigasで追加する契約として扱う。

現在採用する[cv2-enumerate-cameras 1.4.0](https://github.com/lukehugh/cv2_enumerate_cameras)のローカル実装を確認した。WindowsはMSMF/DirectShow、LinuxはGStreamer/V4L2、macOSはAVFoundationの列挙を持つ。`CAP_ANY`の列挙結果は複数方式の合成と番号の符号化を行うため、既存のDirectShow番号をそのまま別方式へ渡す変更にはしない。[OpenCVの実行時API選択](https://docs.opencv.org/4.13.0/d0/da7/videoio_overview.html)と利用可能な方式を確認し、列挙したAPIと接続APIを一致させる。

| OS | 優先方式 | 代替候補と識別 |
|---|---|---|
| Windows | DirectShow | 同じ非空の機器識別子が一意に一致するMSMF候補。名前・VID/PID・番号から同一と推測しない |
| Linux | V4L2 | 利用可能なGStreamerで同じデバイスノードへ解決できる候補。保存用には取得可能なby-id/by-path等を使い、video番号を恒久IDとしない |
| macOS | AVFoundation | 現依存に第2方式はない。uniqueIDを記憶し、接続直前の列挙へ解決する。OpenCVの列挙順との対応は実機受入対象 |

表は候補の優先順であり、各方式の利用可能性を保証しない。OpenCVのカメラ用registryに登録され、`hasBackend(api)`が真になる方式だけを実際の列挙・接続候補にする。使用した環境での可否と実機で確認できなかった代替方式は、実機記録に分けて記す。

保存する機器識別子、表示名、方式ごとの一時的な番号を分離する。既存Windowsの保存パスは意味を維持し、別OSの機器へ読み替えない。画面にAPI選択やリソースパスの手入力を増やさず、同一機器の複数方式をまとめて表示する。一意に照合できない代替候補は自動選択しない。識別子のない汎用番号探索は自動フォールバック対象にせず、必要になった時点で一時選択と保存・再選択の契約を別途設計する。

代替試行は、接続要求から最初の有効Frameを取得する前までに限定する。開始失敗した候補のrelease正常復帰、子プロセスの正常終了、親の資源回収を確認し、未試行の同一機器候補だけへ進む。一つの接続要求では最大2候補を同じ世代で試す。強制終了、終了未確認、停止・アプリ終了要求があれば次を開かない。固着したopenは既存の期限と隔離で終了させ、強制終了を正常解放として扱わない。全候補を通じた開始期限を持ち、途中の失敗理由は診断へ保持し、最終失敗または最初の有効Frameで接続結果を確定する。取得開始後の自動再接続やダミーへの切替は行わない。

カメラ取得層からWindows以外を一律拒否する条件を外すが、アプリ全体の他OS対応を完了とはしない。既定設定パスのLOCALAPPDATA依存とWindows限定CI、macOSのカメラ権限・列挙対応、Linuxのデバイス権限・安定識別子は別に確認が必要である。OS別の分岐・代替制御は機器非依存試験で検証し、他OSの実機確認は未検証として記録する。
