# U03 レビュー反映後の実機・画面確認

[レビュー反映仕様](VIDEO_REVIEW_REFINEMENT.md)の追加要件を確認する記録。以前の画面の結果は[M2受入](../unit_022/HARDWARE_ACCEPTANCE.md)に保持し、今回の実装の確認と区別する。

## 読み取り境界の実機確認

2026-11-11、`bc3d3a2`（取得実装はR2 `284fb74`）で実施。Windows / Python 3.12.10、Live Gamer 4K 2.1系（OS表示名`USB Video Device`、VID 07CA / PID 0575）、DirectShow、要求1920×1080・60 FPS。機器は列挙結果から内部のDevicePathで一意に照合し、取得を一度だけ開始した。画面選択UIはこの試験の対象外。

`uv run --no-sync python tmp/u03/reader_hardware.py`を実行し、取得サービスから2つのCaptureReaderを作成した。観測相当の読み手は最初のFrameを保持し、プレビュー相当の読み手は20msごとにsnapshotを参照した。実MCP、画像のエンコード・配送負荷を含まない。

| 項目 | 結果 |
|---|---|
| 取得画像 | 1920×1080。ファイアレッドのタイトル画面、ゲーム名と著作権表記を画像で確認 |
| 読み取り期間 | 8.06秒 |
| 取得連番 | 1→472、同じ接続世代 |
| 参照した異なる画像 | 373枚。全フレーム録画ではなく最新画像の間欠参照 |
| 取得レート | 機器報告60.00024 FPS、ホスト実測58.7575 FPS |
| 保持したFrame | 画素bytesが不変。保持中も別readerと取得が進行 |
| 切断・終了 | 両readerの新しいsnapshotはframeなし、cleanup=graceful、監視スレッド停止、残存子0 |

画像の標準偏差90.87、最小0・最大255を測定し、画像を開いて内容も確認した。統計値だけで映像の正しさを判断していない。画像・JSON・プローブは作業用の`tmp/u03/reader-hardware.*`と`reader_hardware.py`に保存した。製品の観測保存機能を実装したという意味ではない。

## 新UIとの結合

2026-11-11、R4の製品コードを固定して実行した（同じ製品差分を`2ffb799`へコミット）。実機は上記と同じ。`uv run --no-sync python tmp/u03/final_hardware.py`でApplicationShellと実際のQtウィジェットを使い、独立した設定ファイルで次の順序を確認した。Qtはoffscreenで描画したため、デスクトップ上のマウス操作や実モニターDPIの検証とは区別する。

1. 保存済みの機器へ、事前の一覧更新なしで接続。実映像と`USB Video Device`の表示名を確認した。
2. 映像取得中に表示メニューからHD→WQHD→4K→FullHDを選択し、それぞれ保存成功後に反映した。接続世代は1のまま、取得連番は26→87→149→211へ進んだ。別readerが保持した最初のFrameの画素も不変だった。
3. 約10秒の取得後に切断。画像の失効とgraceful解放を確認し、一覧更新を実行した。設定の表示名`USB Video Device`を選んで保存し、内部の保存値が同じ機器に対応することを確認した。
4. 再接続で世代2の実映像を約10秒表示し、主画面を閉じた。最終状態closed / graceful、取得監視・設定I/O・Codex用サービスの全スレッド停止、残存子プロセス0を確認した。

取得寸法は両接続とも1920×1080。接続要求から最初の画像まで約3.26秒 / 3.52秒、停止直前のホスト実測は59.21 / 59.61 FPS、機器報告は60.00024 FPSだった。最初の停止状態からidleの観測までは約80ms（20ms間隔の状態観測）。光学遅延や表示FPSの測定値ではない。ログは`tmp/u03/final-hardware.json`、描画結果は`final-hardware-*.png`へ保存した。

## 配置と文言の確認

`tmp/u03/render_settings_review.py`と`render_main_review.py`で製品のQtウィジェットを描画し、画像を開いて確認した。offscreen環境はシステムフォント一覧が空だったため、検証ハーネスだけにWindowsのMeiryo UI 9ptを明示した。製品のフォント設定は変更していない。

設定3タブでは、映像機器の表示名一覧・更新、取得/表示FPSとウィンドウサイズ、一行のモデル/エフォート/シリアル設定、共通の保存/再読込/閉じるが収まる。機器パスの入力欄、取得幅・高さの欄はなく、保存先は読取専用の一行欄。主画面には機器名・短い状態・接続/切断を表示し、FPS・ピクセル寸法・DevicePathの常設欄や説明本文はない。実映像の日本語タイトル、著作権表記、縦横比も確認した。

| 仮定した作業領域 | 確認した配置 |
|---|---|
| 4096×2400論理px | HD 1280×720、FullHD 1920×1080、WQHD 2560×1440、4K 3840×2160のウィンドウ。いずれも枠を含め領域内に収まり、会話欄と操作部品が見える |
| 800×800論理px | 4種類とも枠800×451、内容796×447へ縮小。プレビューは残り領域へ収まり、切断・設定・会話操作が見える |

上記は指定した作業領域でのQt配置計算・描画であり、実モニターの4K表示や複数DPI環境を確認した結果ではない。新UIの代表描画、実機からの画素取得、実GUI経路の保存・表示切替・終了をそれぞれ分けて記録した。

## 未検証・対象外

物理抜去、HDMI信号喪失、実ドライバー固着時の強制終了、光学的遅延、長時間連続運転、他機器・他モード、複数モニターのDPI切替は今回未検証。自動試験の故障注入とは分ける。MCP接続・要求後の画像確定・保存はU04、ゲーム入力と即時停止はU05であり、今回の成功に含まない。
