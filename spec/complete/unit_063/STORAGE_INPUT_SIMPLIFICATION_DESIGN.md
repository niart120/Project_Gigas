## 5. 責務と契約

### 5.1 保存（合意済み）

**採用方針（2026-11-14ユーザー確認）:** `生成元 → RecordingService → ProjectWriter → PNG / JSONL`を維持し、writerは保存先、共通の記録形式、追記順、書込失敗を扱う。内容の意味を再判定する保証は削る。「生成元が保証する」とは必ず検査関数を置く意味ではなく、生成処理・外部応答の採用・対応する試験で成立させる意味とする。以下の契約と検査の扱いを採用する。実装・検証の完了とは区別する。

#### 新規記録の検査と生成経路

変更前は[project.py](../../../src/gigas/storage/project.py)の`record_dialogue`、`record_thread`、`record`、`_validate_dialogue`、`_validate_observation`、`_append_event`に検査があった。次の表は削減対象と担当の対応を示す。

| 変更前にwriterが検査していたもの | 生成経路・実際に守るもの | 担当と扱い |
|---|---|---|
| 対話種別が`dialogue.`で始まり、後ろが空でない | サービスが公開イベントを選び、ConversationResourcesが接頭辞を付ける。writerは保存してよい内容かまでは判定していない | サービスのイベント選択と組立で成立させる。writerの接頭辞検査は削り、別の検査を追加しない |
| thread/turn IDが文字列で、空白だけではない | thread開始応答とturn採用時に接続側が非空文字列を確認し、会話処理がそのIDを渡す。writerの検査は実在・帰属を証明しない | 応答を使って会話を進めるための既存の境界検査を残す。保存時の再検査と空白だけの値を追加拒否する保証は削る。接続側へstrip検査を移さない |
| 対話payload/contentがdict | payloadはwriter自身が組み立て、contentはサービスの辞書組立・公開イベントの変換で作る | 組立と試験で形式を保つ。writerのdict再検査を削り、検査付きdataclassへ置換しない |
| 対話受信時刻・観測取得時刻がUTCの文字列形式 | RecordingServiceがUTC現在時刻を生成。観測は取得時刻を引き継ぐ。writerが再び文字列を解析しても時刻の正確さは証明できない | 取得側・記録受付側の時刻生成を維持し、保存時の字句検査は削る。単独呼出しの任意文字列まで整形・補正しない |
| 観測IDが`obs-UUID4`、画像パスが`observations/<ID>.png` | Observation.from_frameがUUID4を生成し、image_pathプロパティがIDから算出する。IDだけは書込先へ影響する | writerで保存先を制約する。ID検査後に固定ディレクトリとIDからパスを作り、その同じ値を記録する。算出済みパスを再比較する検査は不要 |
| Frameの世代・連番がbool以外の正整数 | 取得側のカウンターを引き継ぐ。永続的な観測識別子ではなく、現在は読込側も意味を検査しない | writerの厳密型・正数検査を削る。生成側にbool除外検査を新設しない。既存Frameの契約を強化しない |
| 元寸法16..3840×16..2160、出力寸法が正で元以下、MIMEがPNG | Observation.from_frameが対応寸法を確認して縮小・PNG符号化する。MIMEは固定プロパティ。writerはPNG本体と寸法の一致を検査していない | 符号化に必要な既存検査・変換・符号化結果確認を残す。writerの再検査は削る。保存用のPNG再デコード・内容照合は追加しない |
| contentの事前JSON化、その後イベント全体のJSON化 | contentは現在二度直列化される。JSON化不能値・NaN等を実際に拒否するのは直列化処理 | writerでイベント全体を一度だけ`json.dumps(..., allow_nan=False)`する。独自の再帰検証器は作らない |

生成経路の根拠は[会話応答の採用](../../../src/gigas/runtime/codex/_conversation_protocol.py)、[会話記録の組立](../../../src/gigas/services/_conversation_resources.py)、[受付時の複製・時刻生成](../../../src/gigas/services/recording.py)、[観測の生成](../../../src/gigas/game_io/observation.py)。公開内容の選択・秘密値の除外は会話側の責務として残す。writerに任意のcontentを渡しても秘密値を除外できる保証は、現行にもない。

`obs-UUID4`という厳密な形式そのものが、パス保全に必須なわけではない。必要なのは固定した保存先から外れないこと。ただし今回は既存の短いID検査をその境界だけに残し、新しい汎用パス検証を増やさない。IDのUUID4生成規則は変えない。プロジェクト内の外部編集・リンク差替えまで完全に隔離する保証は追加しない。

`record_input`には内容の再検査は既にない。入力の実行可否は入力の開始前に決まり、writerは実行結果を保存する。入力側の検査を保存へ戻さない。非同期保存前のcontentの複製は、受付後の変更で記録内容が変わるのを防ぐために残す。これは妥当性検査ではない。

#### 読込時に必要な条件

読込対象は既存ファイルであり、現在の生成経路を通った値とは扱わない。ただし「現在の生成形式と完全一致するか」の検査にはしない。

| 現在の検査 | 採用 | 残す理由・失う保証 |
|---|---|---|
| UTF-8、JSON object、対応schema、既存のNaN/Infinityリテラル拒否 | 残す | 対応形式の記録を読み、同じ形式で追記する境界。payloadの意味検査とは分け、独自の再帰検証は加えない |
| metadataのproject IDが正規のUUID4 | 非空文字列だけに縮小 | projectの照合値として必要だが、UUIDの版・大文字小文字は照合に不要 |
| metadataの作成時刻、イベントのID・発生時刻 | 読込時の検査を削る | 採番・追記に使わない。形式だけでなく欠落・型違いもwriterの拒否条件にしない。新規生成時は従来の項目・形式を維持する |
| 保存ディレクトリの存在、JSONLを開けること | 残す | 書込対象として成立するかを確認する。不完全な既存projectを自動作成し直さない |
| 各行の改行終端 | 残す | 不完全な末尾へ次のJSONを連結して破損を広げない |
| 対応schema、metadataと同じproject ID | 残す | 別projectや別形式の記録が混ざったまま追記しない |
| bool以外の正整数sequence、前行より大きいこと | 残す | 追記順と次の採番の根拠。連続性は要求せず、欠番は従来どおり許す |
| 非空文字列のtype、payloadキーの存在 | 残す | 追記の物理的安全性ではなく、最低限「種別と内容を持つイベント列」であることを守る。既知種別・payloadの型・意味は制限しない |

type/payloadの検査は採番だけなら不要である。今回は共通記録形式の小さい契約として残す。「全てがデータ損失防止に必須」とは説明しない。過去画像の存在・内容、会話IDの実在、event IDの重複、payload中の画像パスは全件検査しない。

#### 保存処理の保全と寿命

| 現行の処理・条件 | 担当と扱い |
|---|---|
| 新規projectの既存ディレクトリ拒否、memory入口の既存ファイル保持 | writerの作成処理で残す。mkdir・排他的作成を使い、失敗後の自動初期化や上書きをしない |
| OSロック、操作中のmutex、close済み拒否 | writerで残す。協調する別プロセスと、同じwriterへの同時操作、寿命外の書込を区別する。RecordingServiceは非同期要求の順序と回収を担当する |
| 画像の一時ファイル、既存画像へのrename拒否 | writerで残す。既存画像を守り、書込途中の画像を確定パスへ公開しない。OSの失敗結果を使い、存在確認と上書きの独自手順を追加しない |
| JSONLの短いwriteの検出、追記失敗後の受付停止 | writerで残す。`_next_sequence=None`の間は追記を拒否し、別の復旧フラグを増やさない |
| 明示reloadとproject ID不変の確認 | writerで残す。原本を検査して次sequenceを得る。切詰め・修復・失敗した保存の再送はしない |
| metadata・PNG・JSONLの明示flush/fsync | 削る。通常write/closeで完了とし、安定記憶への同期を保証しない |
| 受付済み保存の回収とwriter closeの順序 | RecordingServiceと資源所有者に残す。書込終了前にwriterを閉じない。保存失敗は入力停止・観測失敗へ変換しない |

#### APIの前提と失敗の扱い

直接呼出しにも、内容が正しい値を渡す前提を明記する。ただし、その前提への違反を一律に検出する約束はしない。JSON化できる意味上の不正値は、そのまま保存される場合がある。空のイベント種別など、直接呼出しで共通形式の前提まで破れば、再読込時に拒否される記録も作り得る。「任意の不正値を渡しても再読込できる記録しか作らない」という保証は残さない。自動補正・黙った破棄・別経路での再検査は追加しない。writerが「完全に妥当な対話・観測だけを保存する」契約を廃止する。

残す失敗は、保存先制約・利用不能・I/O失敗を`ProjectError`、同時操作を`ProjectBusyError`として報告する。JSON直列化の`TypeError`・`ValueError`もその一か所で`ProjectError`へ変換する。無効なオブジェクトによる任意の属性参照失敗等まで、この例外へ統一する保証は設けない。

イベントのJSON化とUTF-8の行データ作成を、JSONLへのI/Oより先に一度だけ行う。失敗段階と次の保存の扱いは以下に固定し、復旧用の状態を増やさない。

| 失敗段階 | 保存物・採番・次の受付 |
|---|---|
| 画像IDの拒否、画像のwrite/close/rename失敗 | JSONLへ進まず、次sequenceは変えない。既存画像を保持し、writerは継続利用できる。一時ファイルの後始末は現行の範囲で行う |
| イベントのJSON化・UTF-8変換でTypeError/ValueError | ProjectErrorとして報告。JSONLへ触れていないため、次sequenceは変えず継続利用できる。観測は画像公開後の行データ作成なので、画像だけが残る場合がある |
| JSONL追記処理のopen/write/file closeでOSError、または短いwrite | 原本を保持し、既存の`_next_sequence=None`で追記を止める。どこまで書けたかを推測して分岐せず、明示reloadで確認する |
| reloadで完全な行まで読める | 最後のsequenceから採番を再開する。失敗した保存の自動再送はしない |
| reloadで不完全行・不整合を検出 | 追記拒否を維持する。切詰め・修復・欠落行の補完はしない |

ここでいうfile closeは各ファイルへの書込を終える処理であり、writerの所有ロックを解放する`ProjectWriter.close()`とは別である。writer終了時の所有権解放失敗を、JSONL追記結果不明として扱う契約は追加しない。画像だけが残る部分失敗をrollbackで隠さず、「失敗なら何も残らない」という契約も追加しない。

内容の妥当性を保存時に拒否する保証を廃止し、読込時には共通記録形式までを残す。任意の不正な単独API利用を救うために、生成元の検査を増やさない。

### 5.2 入力（生成時保証を維持する設計）

**設計方針:** InputStateとInputStepは、通常のコンストラクタが成功した時点で、それぞれの不変条件を満たす。parser経由と直接構築を同じ生成処理へ通す。生成後は値域・重複・press/waitの整合を再検査せず、現在の機器との適合だけをサービスが判断する。unit_066で実装・検証した。

既存の`frozen=True, slots=True`のdataclassと`__post_init__`を使う構成を基本とする。入力値を修正して受理せず、不変条件違反は`InvalidSequenceError`として生成を失敗させる。新しいPress/Waitクラス、ValidatedSequence、検査を迂回する別コンストラクタ、生成許可tokenは追加しない。通常の公開APIによる生成・更新を保証範囲とし、Pythonの強制的な属性書換え等まで封じる仕組みにはしない。

#### InputStateが生成時に保証する条件

| 要素 | 不変条件 | 理由 |
|---|---|---|
| buttons | 文字列要素のtuple。空tupleは可。重複なし | 不変な完全状態として保持する。重複は現行encoderのビット値加算で別のボタン値になる |
| 方向 | UPとDOWN、LEFTとRIGHTをそれぞれ同時に含まない | 共通の方向表現に一意に変換する。隣接二方向は許す |
| left_stick / right_stick | 各々長さ2のtuple。各値はbool以外の整数、-100..100 | 丸め・クリップ・暗黙変換を不要にする |
| touch | None、または長さ2のtuple。bool以外の整数でx=0..319、y=0..239 | Noneが解除、(0, 0)は有効な接触位置。座標の真偽値で解除判定しない |
| 保持方法 | 構築後にフィールドと保持した列を変更できず、以前の入力状態を参照しない | 生成時に成立した条件を、非同期実行中も保つ |

InputState単体ではneutralを許す。neutralはbuttonsが空、両stickが(0, 0)、touchがNoneの状態。省略フィールドもこの値となる。

ボタン名の選択機器での対応可否は不変条件に含めない。たとえばSTARTを持つ状態は構築できてもCH552では実行できない。未知のボタン名も機器能力検査で拒否し、共通の全機器ボタン名登録表は新設しない。生成成功は共通形式の成立を意味し、どの機器でも符号化・実行可能という意味ではない。

#### InputStepが生成時に保証する条件

| 要素 | 不変条件 | 理由 |
|---|---|---|
| kind | pressまたはwait | 実行側が未知種別の解釈や補正をしない |
| duration_ms | bool以外の正整数。固定上限は設けない | 一つの操作時間を明確にする。小数・文字列の変換はしない |
| state | 生成済みのInputState | InputStateの値域・ボタン条件は検査し直さず、その型の生成時保証を利用する |
| kindとstateの関係 | pressは非neutral、waitはneutral | 入力漏れや、waitなのに入力状態を持つ矛盾を生成時に拒否する |
| 保持方法 | 構築後にkind・duration・state参照を変更できない | 実行開始後に操作の意味が変わらない |

`InputStep("wait", 100, InputState(buttons=("A",)))`は生成に失敗する。直接構築にも同じ保証を与えるため、二つの既存クラスのまま生成時に一度確認する。InputStepがInputStateの各フィールドをもう一度走査することはしない。

空press拒否は機器保護のためだけではなく、pressとwaitの意味を分ける契約として残す。touch=(0, 0)のpressは非neutralなので有効。InputState単体のneutralは接続時・解除時にも必要であり、InputStepのpress条件をInputStateへ持ち込まない。

#### parser・生成処理・サービス・encoderの分担

```mermaid
flowchart LR
    J[外部JSON] --> P[parse_sequence: 形式を読み取る]
    P --> S[InputState: 共通状態を生成]
    S --> T[InputStep: 操作を生成]
    T --> Q[不変な操作列]
    Q --> A[会話の受付: 停止・切断中を拒否]
    A --> I[InputService.start: 機器・BUSY・全列の能力確認]
    I --> E[SerialInput.send / encode_state]
    E --> W[serial.write]
```

| 所有者 | 担当 | 担当しないこと |
|---|---|---|
| parser | 非空JSON配列、要素object、必要項目・未知項目、press/waitごとの入力形式、座標objectのx/y、buttons配列を読み取り、既定値を補って生成処理へ渡す | 時間・座標の値域、重複・反対方向、neutral整合の再判定。機器能力検査 |
| InputState生成 | 上表の形状・要素型・値域・状態内部の不変条件を成立させる | 機器選択、JSONの項目名解釈、I/O |
| InputStep生成 | 種別・時間・InputState型・種別と状態の関係を成立させる | InputState内部の再検査、機器能力検査 |
| InputService | 使用可能な機器とBUSYを確認し、選択機器の能力を列全体へ確認してから実行taskを登録する | InputStep/InputStateの成立済み条件の再検査 |
| encoder | 機器に適合するInputStateを完全なフレームへ変換する | 値域・重複・機器能力の再検査、前回状態の保持 |

parserはJSONのbuttons配列をtupleへ、座標objectを(x, y)へ変換する。元のJSONを保持しない。waitには既定のneutralを渡すが、生成処理のwait整合検査は直接構築と同じ経路で行われる。全要素の生成が成功してからtupleを返すので、後方の不正要素で失敗しても操作は開始しない。MCPはparserまたは生成処理の`InvalidSequenceError`を既存の`INVALID_SEQUENCE`応答へ変換する。

JSONから型付き引数を取り出すための型確認と、公開コンストラクタの型保証には小さい重なりが残り得る。たとえばparserが座標の整数型を確認して渡しても、直接構築を受けるInputStateにも型確認は必要になる。ここを消すために未検証値をcastしたり、生成時検査を迂回したりしない。**値域・重複・neutral整合の規則は生成処理だけに置き、生成済みの値に対する検査を削る**。parserでのkind判別もJSONの読取分岐であり、InputStepの種別保証とは役割を分ける。

非空であることは操作列全体の条件であり、InputStep単体からは保証できない。parserは非空のtupleを返し、サービスの内部APIには非空の`tuple[InputStep, ...]`を渡す前提を明記する。サービスの空列再検査は削る。直接呼出しにも非空tupleを渡す前提を課し、空列を渡した場合の拒否コードや副作用なしは保証しない。型だけで列の非空まで証明したとは記さない。非空列専用の新しい型や実行済み・検証済みフラグは作らない。

#### 現行から削る重複と残す生成処理

現行経路と生成箇所の根拠は[JSON解析・内部値](../../../src/gigas/game_io/input/models.py)、[MCP受付](../../../src/gigas/mcp/game_io.py)、[入力実行](../../../src/gigas/services/input.py)、[符号化](../../../src/gigas/game_io/input/protocol.py)、[シリアル送信](../../../src/gigas/game_io/input/serial.py)、[接続設定](../../../src/gigas/game_io/input/config.py)。製品の操作用InputStepはparserが生成し、接続・解除用neutralはサービスとSerialInputが直接生成する。

| 現行の処理 | 改訂後 |
|---|---|
| parserの時間・座標の値域検査と構築時の同じ検査 | 値域の規則はInputStep/InputState生成時に一本化する。JSONの読取・型の絞込みはparserに残す |
| InputState/InputStepの`__post_init__` | 全廃しない。二つのクラスそれぞれの不変条件を一度成立させる生成処理として残す |
| 任意protocol付きparser | protocol引数を削る。機器選択前にも共通状態を生成できるようにする |
| サービスとencoderの能力検査 | サービス開始前の全列検査だけにする。未知・非対応ボタン、非対応touchをそこで拒否する |
| 固定neutralの直接構築 | 同じInputStateの生成処理を通す。専用factoryや検査省略経路は作らない |
| 不正な直接構築を拒否する公開保証 | 不変条件の範囲で維持する。選択機器への適合や実送信成功の保証とは区別する |

開始時に機器を選び、全列能力検査とtask登録までは同期的に行う。実行taskはその機器を使い、機器切替は既存の停止・回収後に行う。機器適合を各ステップで確認し直すことや、検証時の機器ID・世代を別途保持することは不要。

直接構築と単独encoderの公開名は残す。構築に失敗すればオブジェクトは返らない。構築に成功しても選択機器が対応しない場合はあるので、単独encoder・低水準sendは機器適合済みの状態を渡す前提とする。この前提違反まで一律に拒否する保証は廃止する。未知protocolを別方式として出力するfallbackは作らず、符号化方式の選択分岐は残す。

既存の`validate_state(state, protocol)`は機器能力だけを確認する関数として残し、InputServiceが使う。単独利用者も必要なら明示的に呼べるが、parser・encoder・sendからは呼ばない。InputStateの共通不変条件まで検査する関数に広げず、別の検証済み型も返さない。

#### テストと公開APIの変更方針

| 境界 | 確認する振る舞い |
|---|---|
| InputState生成 | 直接構築で重複・反対方向・座標範囲外・bool・可変配列などを拒否する。有効なneutral、端点、touch=(0, 0)、機器固有のボタンは構築できる |
| InputStep生成 | 不正な種別・時間・state型、空press、入力を持つwaitを拒否する。有効なInputState内部を検査し直す呼出回数のテストは作らない |
| parser | JSON形式、未知項目、既定値、元JSONからの独立、操作列の非空を確認する。生成処理の例外が外部入口まで届き、後方の不正要素でも操作が始まらないことをMCPとの結合で確認する |
| サービス | 先頭が対応・後方が非対応の列を開始前に拒否し、当該操作の送信がゼロであることを確認する。接続時neutral送信と区別する。内部空列の拒否期待は廃止し、外部の空配列拒否はparserで確認する |
| encoder・送信 | 正常な機器別byte列、停止・解除・BUSY・部分writeを確認する。非対応状態の単独符号化を必ず拒否する試験は廃止する |

変更前の直接構築の拒否試験は`test_direct_state_rejects_out_of_range_coordinates`が中心で、時間・重複・反対方向などはparser経由で確認していた。unit_066ではencoder呼出しを外し、共通条件の試験を生成境界へ整理した。InputStepへ非InputStateを渡す場合、入力を持つwait、可変列の直接構築など、JSON経由では確認できない条件も生成境界で確認した。

parserには表現形式と代表的な生成失敗の伝播を残す。protocol引数の撤去時に、既存の未知ボタン・別機器のボタン・非対応touchの拒否期待を失わないよう、サービスの全列拒否へ対応付ける。HTTPでは後方要素の生成失敗と機器非対応をそれぞれ代表例で確認する。全境界へ同じ不正値の組合せを複製しない。

公開文書では「InputState/InputStep生成時の共通条件」と「サービス開始時の機器適合」を分ける。外部JSONの実行例はparserからサービスへ通し、直接構築例は生成時の拒否保証を明記する。parserのprotocol引数とencoderの能力拒否保証の変更は、実装と同時に文書・docstringへ反映する。

### 5.3 保存と入力の境界の整合

保存内容の意味検査を削り、入力値の生成時保証を残すことは矛盾しない。保存は原記録として受け取った内容を保持する境界であり、操作の実行可否を決める境界ではない。InputState/InputStepは後段でそのまま操作へ変換するため、生成時に共通の不変条件を成立させる。すべてのdataclassへ生成時検査を追加する方針には広げない。

| 境界・前提 | 誰が成立させるか | 重複・抜けを作らない扱い |
|---|---|---|
| 操作列の共通条件 | parserが全要素を生成し、各コンストラクタが不変条件を保証 | 生成失敗ではサービスへ渡さない。サービス・writer・encoderで共通条件を再検査しない |
| 非空で不変な操作列 | parserの戻り値、または直接呼出側が構築した非空tuple | 要素の生成保証とは別のAPI前提。新しい列クラスは作らず、直接空列の拒否保証は廃止する |
| 選択機器への適合 | InputServiceが現在の機器へ全列を確認 | 未知ボタンはここで拒否する。任意の文字列を含むInputStateの構築成功を、実行可能と読み替えない |
| 操作と記録の関係 | `_game_io_tools.act_and_observe`が受付済み操作・実行結果をRecordingServiceへ提出 | 入力は保存完了を待たず、保存失敗で操作結果を変更しない。writerへ実行許可や停止状態を持たせない |
| 過去の入力payload | 保存読込は共通記録形式だけを確認 | 過去payloadからInputStepを再構築しない。実行や機器適合を過去記録へ遡及して要求しない |
| 保存先と機器の寿命 | writer、RecordingService、InputService、会話の各所有者 | 現在の所有・回収を維持し、検証済み・再受付可能・保存完了による許可などの状態を追加しない |

入力値の生成失敗・機器能力拒否と、開始後の送信失敗は分ける。前者は当該操作を送らない。後者は途中まで実行された可能性を既存の結果へ残し、停止・解除・回収を行う。この区別を単一の「不正な要求」へまとめない。

| 残件 | 現行で確認した根拠 | 後続での扱い |
|---|---|---|
| SerialConfigの再解決 | 製品は設定適用時にresolve_serial_configで構築し、_open_nativeでも同じ値を再解決する | 有効なSerialConfigを受ける前提とport実在確認を分けて再解決を削る。設定ファイル検証・直接構築APIの一般化は行わない |
| CaptureServiceのpending未設定分岐 | Condition.wait_forがclosingまたはpending有りを待ち、同じlock内でclosingを除外した後にもpending None分岐がある | 待機から要求取出しまでの制御フローを整理する。None分岐をcast/ignore/assertへ置換するだけにしない |
| stdio readerのprotocol未設定分岐 | _start_processがprotocolを受け取った後だけ_read_stdoutのtaskを作る | 起動で得たprotocolをreaderへ渡し、寿命外の起動を入口の構造で除く。終了・例外処理は維持する |

これらの変更時には、対応するserial・capture service・stdio transport試験と型検査を行う。保存・操作列の検査を増やす理由にはしない。追加の削除候補を発見しても本書の範囲を自動拡張しない。
