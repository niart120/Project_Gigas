# U05 操作と停止 親仕様

## 1. 目的・状態・起点

Codexの通常ターンから有限の操作列を実機へ送り、解除後の観測を返す。利用者の停止をCodex応答待ちにせず、記録と入力許可を含む一連の経路として確認する。

状態: **complete（製品結合・対象構成の受入完了）**。[M0子仕様](../../complete/unit_036/INPUT_AND_STOP_DESIGN.md)が設計、[M1子仕様](../../complete/unit_038/INPUT_EXECUTION_AND_OBSERVATION.md)が内部実装、[M2子仕様](../unit_042/INPUT_APPLICATION_INTEGRATION.md)が製品結合と受入を所有する。同期MCPの65秒要求・短縮期限を模擬機器で確認し、製品GUI・実モデル・CH552による入力、設定モーダルからの停止、映像・記録、通常終了を確認した。全体660件と最終gate・再レビューは成功した。

| 起点 | 内容 | 参照 |
|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 利用者が操作依頼を明示的に開始する。Codexがact_and_observeを呼び、操作後の画面を確認する。途中でGUIから停止すると後続入力が実行されない。

[境界整理](../../complete/unit_039/INPUT_OBSERVATION_SIMPLIFICATION.md)で観測入口と保存の所有を整理し、入力記録の検査、停止時の送出結果、後付けturn IDを修正した。最新キャッシュへの統一は[観測簡素化](../../complete/unit_040/LATEST_CACHE_OBSERVATION.md)で扱う。

## 2. 前提と着手条件

GUIの依頼入力・停止導線は[実装整理](../../complete/unit_027/IMPLEMENTATION_SIMPLIFICATION.md)と採用済みの[主画面とメッセージ操作](../../initial/10-ui-interaction.md)に従う。M0で設定モーダル表示中を含む通常ターンの即時停止の入口を具体化し、M2で物理入力と結合確認する。映像機器の「未接続」による取得終了と、推論中断・物理入力の停止は別の責務。U06 M1のUI置換、M2のGoal保持／破棄・同一セッション再開へ共通停止処理を引き継ぐ。本工程に仮のGoal状態や終了専用経路を作らず、U06の画面完成を実機停止の前提にしない。

[U04](../../complete/unit_009/RECORDED_OBSERVATION.md)の観測・記録・MCP、[U02](../../complete/unit_007/CODEX_CONNECTION.md)の通常ターン・要求応答・中断を利用する。入力を公開する前にMCP接続と実行世代の対応・旧要求失効が採用版で成立することを確認する。U01のポート文字列保存は入力接続の成立を意味しない。

操作列の最後の解除・末尾waitが完了した後に、単独observeと同じ処理で最新キャッシュを一度取得する。新しいFrameを待たず、操作前や前回観測と同じFrameも許容する。画像取得時刻やゲームへの入力反映は保証しない。

U02完了後レビューR01は[設定障害時の停止修正](../../complete/unit_019/SESSION_STOP_AVAILABILITY.md)で修正・Qt回帰確認済み。実機入力を公開する前には、設定障害中も物理入力を即時停止できることを本工程で結合確認する。

親仕様は工程全体の受入条件を所有する。M1の実装・検証は子仕様に記録し、残るM2の着手・受入条件は本書6節・10節にまとめる。該当protocolの実機受入を内部試験で代用しない。M2は[アプリ結合](../unit_042/INPUT_APPLICATION_INTEGRATION.md)で進める。

## 3. 対象範囲・対象外

対象: 実デバイスとシリアル仕様の選定、操作列の全体検査、有限時間の実行・待機・取消し・解除、一つの入力所有者、依頼・実行・操作の記録、act_and_observe、GUIの開始・即時停止、通常ターンとの結合を扱う。

対象外: Goalの自動継続、計画的なプレイ終了、停止後の攻略再開、記憶整理、Bluetooth、第三の操作専用MCPツール、dynamic tool、非同期受付・ポーリング、実機へのexactly-once保証は含めない。

| 操作権・MCP | GameIoMcpServerのrun固定Grantと新endpointを対応。停止・通常turn終端で失効。次の明示送信は適用中protocol・対応入力を公開し、unsubscribe→同ID resumeでCodex側を再読込。同期要求は300秒、内部入力の固定上限は設けない。副作用注釈と当該toolだけのapproval_mode=approveを使う | 製品・実モデルの3run、模擬機器の3DS再読込・65秒要求・短縮期限を確認。300秒の実待機は未検証 |
| 記録 | request/run/operationに入力列・実行結果・観測IDを対応付ける。接続情報は通常記録に含めない。開始・結果・画像はすべて非同期で、保存失敗は入力を止めない。同じwriterへの記録を順序化し停止を待たせない | 記録失敗、操作結果不明、観測ID対応、通常終了drain |
