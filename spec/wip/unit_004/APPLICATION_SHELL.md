# U01 M2 アプリ起動・設定画面・終了

## 1. 概要

### 1.1 目的と状態

[親仕様](../unit_001/APP_STARTUP.md)の起動・編集・保存・終了を機器なしで成立させる。2026-11-10に設計をレビューし、画面構成とM1 APIへの接続を改訂した。実装未着手。[M0](../../complete/unit_002/ARCHITECTURE_AND_DEPENDENCIES.md)のQt構成と、実装済みの[M1](../../complete/unit_003/GLOBAL_SETTINGS.md)を使う。

### 1.2 起点と要求差分

[02](../../initial/02-runtime.md)のGUI応答と終了、[05](../../initial/05-implementation.md)のU01完了条件に基づく。今回のユーザーレビューを受け、設定フォームだけでなくメイン画面との関係と後続の配置方針を定める。NyXの配置と設定の呼出しを参考にするが、マクロ実行用の構成全体は移植しない。

初回利用者は設定を開いて編集・保存でき、再起動後も値を確認できる。保存に失敗した利用者は入力を失わず再編集・再試行できる。

実装着手前の追加要件: GUIへの説明文章を原則禁止する。[初期設計01](../../initial/01-overview.md)とAGENTS.mdへ全体規約として反映した。M2はボタン名・項目名・短い状態・確認対象・エラー理由とパス・値のみを表示し、使い方はdocsへ記載する。Codex由来テキストとユーザー入力文章は全体規約の例外だが、M2にCodex表示はない。

## 2. 対象範囲

起動入口、appの組立て、メイン画面、独立した設定ダイアログ、状態・エラー表示、QtのI/O橋渡し、未保存確認、終了結果を実装する。全体画面の領域と担当工程も決める。M0で選定したEssentialsとpytest-qtを追加し、Python範囲・Windows CIを整合させる。

## 3. 対象外

機器列挙・接続、実映像プレビュー、攻略開始・停止、Codex認証、asyncioサービス、プロジェクト操作は実装しない。将来領域の位置を決めることは、機能・空クラス・無効ボタンを一括生成することではない。ドッキング、任意のペイン再配置、画面位置・寸法の永続化、テーマ設定、汎用フォーム生成器は導入しない。

## 5. 振る舞い仕様

### 5.1 起動入口と失敗

project.scriptsに`gigas`を置き、`uv run gigas`と`uv run python -m gigas`が共通のmainを呼ぶ。標準エラーへ診断を出せるコンソール入口を採用し、コンソール非表示のランチャーは追加しない。入口定義はM2、隔離インストールした配布物の起動確認はM3が担当する。

importだけではQApplication・ワーカー・設定ファイルを作らない。appがM1の`default_settings_path()`で保存先を決定し、メイン画面を表示してからワーカーへ読込を要求する。試験ではappへ一時保存先を渡す。ユーザー向けの別パス選択機能やcwdへの代替保存は追加しない。

保存先決定不能など、appが捕捉できる起動失敗は標準エラーと終了コード1にする。部分的に生成したワーカー等があれば同じ終了手順で解放する。通常終了は0。Qtネイティブ側の異常終了まで必ず1へ変換できる契約にはしない。

設定ファイルの読込失敗はGUIに残って再読込・終了を選べる状態とし、起動不能とは区別する。修復のため通常終了した場合は0。必須指示リソースはここでは使用せず、欠落だけで画面起動を禁止しない。

### 5.2 メイン画面と段階的な配置

初期設計01はライブプレビュー・計画・依頼・介入・停止等を初期版に含めるが、その詳細画面をU01ですべて実装する計画ではない。05に従い、U03でプレビュー、U07で実行管理と画面を結合する。M2ではその接続先になる主画面と設定への入口を確定する。

M2で実際に表示する画面は次の構成とする。中央には案内文や偽の映像を置かない。

```text
┌ GIGAS ─────────────────────────────────┐
│                                [設定…] │
├────────────────────────────────────────┤
│                                        │
│                                        │
│                                        │
│                                        │
├────────────────────────────────────────┤
│ 設定の読込中／変更なし／未保存／結果   │
└────────────────────────────────────────┘
```

タイトルはGIGAS、上部右側に文字付きの設定ボタン、中央に主表示領域、下端に状態欄を置く。メイン画面の閉じる操作はアプリ終了とする。読込失敗は状態欄へ残し、設定画面に操作・理由・パスの診断を置く。中央への案内文や説明用ツールチップは設けない。設定を自動で開く初回判定は行わず、読込中でも設定画面を開いて進行を確認できる。

全体の配置方針は次の図とする。これは後続仕様の出発点であり、M2で全ペインを作る指示ではない。

### 5.3 設定ダイアログとM1 API

設定はメイン画面に従属する非モーダルのQDialogを1つだけ開く。再度「設定」を押すと同じ画面を前面に出し、未保存値を初期化しない。`show()`と通知を使い、appが参照を保持する。設定を開いている間もメイン画面の終了を受け付ける。閉じる確認も重複生成せず、入れ子の`exec()`で操作を待たない。

上から保存先（読取専用・コピー可能）、映像・入力の組、エージェントの組、結果・エラー欄、下端の「保存」「再読込」「閉じる」を置く。未使用のカテゴリや空タブは作らない。

| 表示項目 | M1のSettings属性 | 編集方法と意味 |
|---|---|---|
| 映像取得元 | capture_device | 文字列。U03で識別・列挙方式を具体化する希望値 |
| シリアルポート | serial_port | 文字列。U04で接続時に確認する希望値 |
| モデル | model | 文字列。モデル一覧・有効性の確認はU06 |
| エフォート | effort | 文字列。固定候補の列挙はU06で判断 |
| 認証方式 | auth_method | ChatGPT / APIキーの選択をchatgpt / api_keyへ対応。キー入力欄やログイン済み表示は置かない |

4つの文字列欄は空欄を許し、値を勝手にtrim・大文字化・機器ID変換しない。手編集された複数行文字列もM1では有効なので、編集部品は改行を含む値を保持できるものを使う。既知モデルやエフォートの固定リスト、COM番号の正規表現をM2で追加しない。M1の許容値を画面表示だけで欠落・変換させない。

appは`load_settings(path) -> Settings`の戻り値を基準値と編集値に置き、`save_settings(path, settings) -> None`には保存開始時の不変なSettingsを渡す。保存が例外なく完了したときだけその値を基準値にする。保存結果にSettingsやTOML文書が返るとは仮定せず、成功後の余分な再読込も要求しない。ファイル内容とコメント保持はM1に任せる。

未保存は「編集値が最後に読込・保存に成功した基準値と異なること」とする。値を元に戻せば未保存も解除する。ファイルなしの既定値も変更なしとして扱い、開いて閉じただけでは保存確認やファイル作成を行わない。UIは読込成功を「保存済み」と断定せず、「変更なし」と表示する。明示的な保存は変更がなくても許可し、既定値のファイルを作成できる。M1のAPIをファイル有無の検出のために拡張せず、GUIからexists等のI/Oを追加しない。

### 5.4 操作状態・破棄・エラー

| 状態 | 許可する操作 | 結果 |
|---|---|---|
| 読込中 | 設定画面の表示、閉じる要求 | 編集・保存・重複再読込を受け付けず、画面は応答を保つ |
| 読込失敗 | 再読込、閉じる | 保存不可。過去の表示値があれば保持するが編集も停止し、読込成功まで有効な設定と扱わない |
| 編集可能 | 編集、保存、再読込、閉じる | 基準値と編集値を区別する |
| 保存中 | 閉じる要求 | 編集・二重保存・再読込を止め、開始時の値と結果を対応させる |
| 保存失敗 | 再編集、保存の再試行、再読込、閉じる | 基準値を更新せず編集値を保持する。変更なしの明示保存に失敗した場合もエラーは表示する |

設定画面の「閉じる」・×・Escは同じ閉じる要求に集約する。設定画面だけを閉じる場合と、メイン画面からアプリ全体を終了する場合を区別する。

| 操作 | 未保存の場合の選択 | 遷移 |
|---|---|---|
| 設定を閉じる／アプリ終了 | 保存・破棄・取消し | 保存成功後に元の閉じる要求を続行。失敗なら閉じる要求を解除し、入力を残す。破棄なら基準値へ戻して閉じる。取消しなら元の編集へ戻る |
| 再読込 | 編集を破棄して再読込・取消し | 前者の選択後だけ読込を始める。成功後に基準値と編集値を置き換える。失敗時は直前の表示値を残して読込失敗状態へ移る |

再読込は保存操作ではないため「保存して再読込」は設けない。破棄はメモリ上の編集を捨てる意味であり、元ファイルを削除しない。再読込に失敗して編集値が残った場合は、閉じる確認を「破棄・取消し」に限定し、読込失敗中の保存を許可しない。残った表示値はコピーできる。初回の読込失敗には未保存値がなく、そのまま閉じられる。

保存中・読込中の閉じる要求は1件だけ保留し、結果処理後に判定する。設定だけの閉鎖待ちにアプリ終了が重なった場合は、対象をアプリ全体へ変更して表示し、同じ結果を待つ。保存失敗なら保留要求を解除する。未保存確認中も編集・I/O・別の閉じる確認を重ねず、確認の取消し・閉じる・Escは取消しにする。設定だけの閉鎖待ちも取消し可能とし、I/O自体は継続する。

SettingsErrorは操作名、保存先、理由を画面へ出す。M1の`add_note()`による一時ファイル後始末失敗も詳細として読めるようにする。ファイル本文・例外の原因チェーン全体は表示しない。想定外のExceptionもワーカー境界で失敗として返し、値を保存成功へ変換しない。任意の例外本文に設定値が含まれ得るため、画面には操作名・例外型・保存先と一般的な失敗説明を出す。

手編集はアプリ終了中に行う。構文・型不正は終了後に修正または退避し、再起動する手順をdocsへ書く。GUI内に修復手順の文章は追加しない。再読込は一時的なI/O障害からの復帰にも使えるが、起動中の手編集を安全にする競合解決機能ではない。版管理・移行画面・未知キー警告一覧・自動初期化は設けない。

### 5.5 I/Oと終了

M0で決めたQObjectワーカーとqueued signalを使用する。実行中I/Oは1件で、現在の操作種別と保存開始時の値をappが保持する。読込・保存結果はappが1回受け取り、メイン画面と設定画面へ反映する。設定画面の開閉だけでワーカーを作り直さない。

操作中は新規要求を拒否し、取消し後も実行中I/Oを待つため、M2では要求ID・世代番号・古い結果を捨てる汎用機構は不要と判断する。U07の実行世代は別の責務であり、本判断で削除しない。閉じる要求の取消しはI/Oの取消しや保存の巻戻しではない。

終了は次の段階を分ける。設定ダイアログだけの閉鎖ではワーカーを停止せず、アプリ終了の場合だけ停止する。

1. **結果待ち**: メイン画面を残し、新規I/Oを止める。I/O中なら結果を処理して未保存確認または終了確定へ進む。この間は「終了を取り消す」を使える。取消し後も進行中のI/Oを二重発行せず、戻った成功・失敗を反映する。
2. **終了確定**: I/Oがなく、未保存の選択が解決したらQThreadへquitを送り、以後は終了取消しを受け付けない。停止済みワーカーを再作成して画面へ戻す機能は作らない。
3. **解放確認**: finished通知と非ブロックのwait(0)で終了を確認する。未終了ならタイマーでイベント処理へ戻り、busy loopにしない。M0に従ってワーカーをdeleteLaterで解放し、スレッド終了後に画面とQApplicationを閉じる。最後のウィンドウが閉じたことによる自動終了がこの順序を迂回しないようにする。

終了待ちは直ちに表示し、5秒続いたら待機対象（設定読込／設定保存とパス、またはワーカー終了）を詳しく示す。5秒は表示変更の基準であり、成功・失敗・中断の期限ではない。終了確定前だけ取消し可能であることを表示する。QThread.terminate、実行中スレッドの破棄、長い同期wait/joinは行わない。戻らないOS I/Oをアプリ内で必ず安全に止める保証はない。
