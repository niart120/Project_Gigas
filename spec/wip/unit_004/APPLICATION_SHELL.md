# U01 M2 アプリ起動・設定画面・終了

## 1. 概要

### 1.1 目的と状態

[親仕様](../unit_001/APP_STARTUP.md)の起動・編集・保存・終了を機器なしで成立させる。状態は独立設計案、実装未着手。[M0](../../complete/unit_002/ARCHITECTURE_AND_DEPENDENCIES.md)のQt構成を採用し、[M1](../unit_003/GLOBAL_SETTINGS.md)の保存部品完成後に結合する。

### 1.2 起点と利用場面

[02](../../initial/02-runtime.md)のGUI応答と終了、[05](../../initial/05-implementation.md)のU01完了条件に基づく。初回利用者は設定を編集して保存でき、再起動後も値を確認できる。保存に失敗した利用者は入力を失わず再試行できる。

## 2. 対象範囲

起動入口、appの組立て、設定フォーム、QtのI/O橋渡し、未保存確認、終了結果、エラー通知を実装する。M0で選定したEssentialsとpytest-qtを追加し、Python範囲・Windows CIを整合させる。

## 3. 対象外

接続ボタン、機器列挙、プレビュー、攻略開始・停止、Codex認証、asyncioサービス、プロジェクト切替は実装しない。未接続機能の空クラスや成功応答を置かない。

## 4. 関連文書と責務

配置は[06](../../initial/06-repository.md)に従う。appはQApplication、操作の調整役、QThreadとワーカーの寿命を所有する。uiは操作受付と表示のみ、storageの結果をappが表示可能な値へ変換する。保存成功後の設定値を接続済みと表示しない。

## 5. 振る舞い仕様

### 5.1 起動入口と画面

U01ではproject.scriptsにgigasを置き、`uv run gigas`と`uv run python -m gigas`が共通のmainを呼ぶ設計とする。診断を標準エラーへ出せるコンソール入口を採用し、コンソール非表示のGUI用ランチャーは追加しない。配布物の入口の実生成はM3で確認する。

importだけではQApplication・ワーカー・設定ファイルを作らない。起動時に読込中の画面を表示してI/Oを開始する。GUI初期化前の失敗は標準エラーと終了コード1、通常終了は0。設定読込失敗は修復・再読込が可能な画面状態であり、直ちにプロセス終了しない。

画面にはアプリ名、設定保存先、M1の編集項目、保存・再読込、未保存状態と結果を置く。認証方式の選択と認証済み表示は区別する。モデル・機器の欄には接続時に確認する希望値であることを示す。未実装の攻略操作は表示しない。

### 5.2 状態と操作

| 状態 | 許可する操作 | 結果 |
|---|---|---|
| 読込中 | 終了要求 | 編集・再読込の重複を受け付けず、画面は応答を保つ |
| 読込失敗 | 再読込、終了 | 上書き保存は不可。ファイル本文を表示せず理由とパスを示す |
| 編集可能 | 編集、保存、再読込、終了 | 最後の保存値と編集値を区別する |
| 保存中 | 終了要求 | 二重保存と編集中値の差し替えを拒否し、結果を待つ |
| 保存失敗 | 編集値の確認、再試行または再読込、終了 | 編集値を保持する。再読込で編集を捨てる前に確認する |
| 終了処理中 | 終了要求の取消し | 未終了対象を表示し、新規I/Oを止める |

初回の既定値も未保存として示す。未保存状態の再読込と終了には保存・破棄・取消しを提示する。保存失敗時は終了しない。破棄は編集中の値だけを捨てる操作で、元設定ファイルの削除ではない。

M1レビューに従い、設定の版管理・移行画面・外部編集の競合状態は設けない。手編集はアプリ終了中に行う前提とする。旧設定が現在の型に合わなければ通常の読込失敗として扱い、終了後の修正・退避・再作成を案内する。未知キーの警告一覧は表示しない。

### 5.3 I/Oと終了

M0で決めたQObjectワーカーとqueued signalを使用する。要求に識別子を持たせ、現在待つ要求の結果だけを適用する。実行中I/Oは1件。ワーカーはuiへ触れず、成功または理由付き失敗を必ずappへ返すよう境界で例外を扱う。

閉じる操作を受けても保存中の画面を即座に破棄しない。保存結果を処理した後にquit、finished、終了確認を経て画面を閉じる。終了待ちが5秒続いたら未終了対象を明示し、終了要求を取り消せるようにする。5秒は表示の切替基準であり、処理の強制中断や保存失敗確定の期限ではない。ワーカーをterminateしない。

取消し後もI/Oが動いている限り新規I/Oを受けない。処理が戻れば通常の成功・失敗へ移る。戻らないOS I/Oをアプリ内だけで必ず安全に止める保証はない。画面を無応答にする同期wait/joinは行わない。

## 7. 設計メモ

Qtの採用版で通常のqueued通知はM0で確認済みだが、製品の例外処理・画面寿命・終了競合は未検証。pytest.ini相当の設定でqt_api=pyside6を固定する。offscreenの試験と、Windowsの可視画面での確認を別に記録する。

## 8. 対象ファイル

`src/gigas/__main__.py`、`app/`、`ui/`、GUI結合試験、`pyproject.toml`・`uv.lock`・CI、READMEの起動方法とAGENTS.mdの起動入口を対象とする。requires-pythonはM0の>=3.12,<3.16に揃え、Windows CIに3.13を追加し3.12も残す。

## 9. 検証

すべてnot run。依存同期・lock確認、ruff format/check、ty、unit/integration、uv build、diff checkを実施する。Windows可視画面では初回起動、編集、保存失敗、終了、再起動、プロセス終了を確認し、OSとPython/Qt版を記録する。可視画面の表示品質と操作確認はoffscreen結果で代用しない。

## 10. 先送り事項

インストール済み入口はM3で確認する。サービスループと実行中の機器・Codexの終了は後続工程。現在の設定I/O終了試験を、将来の入力解除保証として扱わない。
