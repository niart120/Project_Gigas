## 5. 整理する振る舞いと維持するもの

### 5.1 選択値と起動・一覧更新

機器欄とメニューのチェックは保存する設定値を示し、実際の取得状態は主画面の映像ステータスで示す。設定を開いたときは最後に正常に読み込んだ／保存した値を編集する。保存機器がAなら、停止中・接続失敗でもAを選択表示し、実状態に合わせて未接続へ書き換えない。フォームの編集値とは別の「接続意図」は持たない。

設定はモーダルとし、開いている間は主画面メニューを操作できない。映像取得・Codex受信などの非同期処理は継続する。

| 場面 | 契約 |
|---|---|
| 保存機器なしで起動 | 未接続を選択表示。取得しない |
| 保存機器Aで起動 | Aを選択表示。起動・設定を開く操作・一覧更新だけでは取得しない |
| 設定でBを選ぶ | 編集値だけBにする。適用まで保存値と取得先は変えない |
| 一覧から保存／編集機器が消えた | 選択値を保持し、別機器や未接続へ自動変更しない。既存一覧の表示名、なければ識別子を値として示す |

同名機器の識別は維持する。一つの識別子につき一候補とし、「保存済み」「選択中」「現在の機器」を別候補にしない。接続中・未確認・未検出によって機器名を入れ替える表示も撤去する。表示名のための新しい永続キャッシュは作らない。

設定／機器メニューを開いた時に、列挙可能なら一覧を取得する。取得中など列挙できないときは既存候補を使用し、後で自動実行する予約は持たない。停止後に一覧更新または開き直しで再取得する。列挙は現在の取得を止めず、失敗しても候補と編集値を失わない。

### 5.2 OK／適用と保存の境界

共通処理は、全項目の検証 → 必要ならファイル保存 → 保存基準値と表示設定の更新 → 映像への反映要求の順とする。全タブを一度に検証し、一部だけ保存しない。未知項目・コメント・文字列値の保持、ファイル置換による原本保護は維持する。設定ファイルが存在し値も同じなら再書込しない。

| 操作 | 契約 |
|---|---|
| 適用 | 全タブの編集値を共通処理へ渡し、画面を維持する |
| OK | 適用と同じ処理を行い、保存成功と反映要求の引渡し後に閉じる。初回フレーム・接続成功・旧機器解放は閉じる条件にしない |
| キャンセル／×／Esc | 未提出の編集を破棄して閉じる。適用済み、または既に保存処理へ提出した操作は巻き戻さない。破棄確認は挟まない |
| メニューで機器を選ぶ | 機器以外の保存値を保ち、同じ保存・映像反映処理を使う。同じ機器の選び直しも受け付ける |
| 表示サイズのメニュー | その表示設定だけを保存・反映する。接続開始・再試行を暗黙に要求しない |

**現行からの変更:** 起動後に保存機器Aが選ばれた状態で、一般タブだけを編集してOK／適用してもAの接続を試みる。明示的な全設定の適用は映像設定も含むためである。取得させない場合は未接続を選ぶ。同じ表示値に対して、過去にコンボを触ったかどうかで結果を変えない。

OK／適用を編集差分だけで無効にしない。無編集でも接続失敗後の再試行ができ、同じ要求条件で取得中なら何も再起動しない。保存後の接続要求が直ちに拒否された場合もOKは閉じて通知へ失敗を残す。入力検証・保存が失敗した場合は閉じず、編集値を保持する。

Codexのモデル・エフォート・認証方式とシリアルポートは、今回の範囲では現在の保存機能を維持する。「全タブの適用」を理由に、接続中モデル変更・認証切替・コントローラー接続を追加しない。接続後の実行設定反映はU06、物理入力はU05の担当とする。

### 5.3 取得開始・切替・未接続

映像への反映は機器識別子・取得FPS・要求解像度の組で判断する。到着画像の寸法・報告FPSとの差を再接続理由にしない。表示FPS・ウィンドウサイズ・プレビュー方式の変更では取得中の機器を開き直さない。

| 反映時の状態と選択 | 結果 |
|---|---|
| 停止中／接続失敗後にAを適用 | 解放確認済みならAの接続を一度試みる。設定が同じなら再保存しない |
| A取得中に同じ取得条件を適用 | 取得を継続し、表示設定などの変更だけ反映 |
| A取得中にB、または取得FPS・要求解像度を変更 | 保存後に旧取得を終了し、解放確認後に新条件で開始 |
| 未接続を適用 | 機器を空文字で保存後、未開始の接続予定を破棄し取得を終了。現在フレームを失効させ、黒い疑似フレームは作らない |
| 接続／切替中に再度適用 | 同じ取得条件なら重複開始しない。異なる条件なら保存成功後の最新一件を反映先とし、旧取得の解放を飛ばさない |

独立した映像接続・停止コマンドを削除する。未接続は次回起動にも残る設定であり、直前の機器を別枠で記憶する一時停止は提供しない。接続失敗・機器抜去で保存値を自動消去せず、自動再接続もしない。

処理中でも保存I/O完了後は未接続を選んで適用できる。A→Bの解放待ち中に未接続を保存したらBを開始しない。A→B→Cなら未開始のBを飛ばし、開始済みならBの解放も確認してCへ進む。操作の列は作らず、取得所有者が最新の反映先一件と処理中資源を持つ。旧世代の通知で反映先や選択値を戻さない。汎用ジョブ管理・自動修復・失敗時の元機器への自動復帰は追加しない。

### 5.4 失敗・復旧

| 失敗 | 保存値・取得・画面 | 次の操作 |
|---|---|---|
| 起動時読込失敗 | 原本を上書きしない。保存・機器操作は禁止し、パスと詳細は参照可能 | ファイルを修正してアプリを再起動 |
| 検証／保存失敗 | 基準値・取得を変更しない。開いている設定の編集値を保持。メニューのチェックは旧保存値へ戻す | 原因を確認して再適用、またはキャンセル |
| 保存後の接続失敗 | 新設定を保持し自動ロールバックしない。適用なら画面維持、OKなら閉じたまま | 同じ機器の再選択／再適用、別機器または未接続を選ぶ |
| 旧取得の終了未確認 | 新設定は保存するが新取得は禁止。未接続を保存しても解放成功とは扱わない | 詳細を確認。解放確認済みに戻るまで新接続を拒否し、機器・残存プロセスの状況を確認 |
| 列挙失敗 | 保存値・編集値・直前の候補を維持。取得中なら継続 | 列挙可能な状態で一覧更新 |

失敗は既存の通知から再確認できる。設定の詳細入口は当該失敗を示し、別操作の最新通知にすり替えない。未接続の保存に失敗した場合、取得が続くことを詳細に明記する。一時停止で保存失敗を迂回する機能は作らない。アプリ終了の資源解放は設定保存と独立して行う。

取得開始・終了の既存期限を維持し、強制終了だけを解放成功とみなさない。保存値と実状態の不一致を説明するための通常時の文章や複数ラベルは追加しない。

### 5.5 保存中・モーダル・アプリ終了

保存I/Oは既存ワーカーで行う。保存中は編集欄とOK／適用、主画面の新しい設定変更を無効にし、一件の提出済み設定を保持する。キャンセル／×／Escは利用可能とする。閉じても提出済みの保存と成功後の反映は継続する。完了までは設定を再度開かせず、非表示の編集画面との同期を行わない。

画面を維持して保存失敗になれば編集値を残す。保存中にキャンセルで閉じた後の失敗は通知へ残し、自動再表示しない。次回は最後の成功設定から開く。明示的に破棄した下書きの復旧機構は作らない。

映像の接続・解放待ちだけで設定全体を操作不能にしない。OK後、またはキャンセルで閉じれば既存のCodex中断・切断へ戻れる。設定を閉じる操作自体はCodexを中断しない。新しい中断ボタン・ショートカットは追加しない。詳細画面も閉じて戻れ、停止要求を保存・接続の完了待ちに積まない。物理入力の即時停止をこの二段階操作で十分とする判断はせず、U05で直接の停止導線と実機解除を設計・検証する。

アプリ終了前の未保存確認は未提出の編集がある場合に維持し、そのキャンセルは終了要求を取り消す。終了確定後は設定I/Oと各サービスの終了を確認し、通常画面へ戻す「終了待ち取消し」は撤去する。保存中の終了要求は実行中I/Oの結果を待つが、未開始の映像接続は開始しない。保存失敗なら終了を確定せず、失敗の確認・再保存または破棄して終了を可能にする。終了未確認を無条件のタイムアウトで成功扱いしない。

### 5.6 削除・削減対象

| 対象 | 範囲と残すもの |
|---|---|
| 設定の再読込 | メニュー・復旧操作・編集中の再読込分岐を撤去。終了中の手編集と起動時読込、原本保護は維持 |
| 映像情報画面と専用計測 | 正常時の情報閲覧画面、専用のFPS計算・保持を撤去対象とする。失敗診断、取得時刻・連番・世代は維持 |
| 残存コードと重複入口 | 非表示の診断欄3個、通知画面の設定ボタン、製品内で不使用の`ApplicationShell.save()`・`select_device()`を参照先ごと整理。公開APIの扱いも実装時に確認 |
| 状態の説明表示 | 設定の機器欄付近の現在機器・接続状態の出し分けを撤去。実状態と取得中の機器名は主画面ステータス、失敗理由は通知詳細へ集約。保存中・保存失敗・一覧検索中／失敗の短い表示は残す |
| 回答カード | 回答中は入力、処理後は短い結果を表示し、手動折りたたみ操作を撤去。処理済みカードは次の通常ターン開始が確認された時に取り除く。ターン終了直後には消さず、結果を確認する時間を残す |

カードは送信ボタンを押しただけでは撤去せず、次ターン開始失敗なら前ターンの結果を保持する。未解決・送信中の要求を表示都合で失効させず、`sent`／`not_sent`／`unknown`の区別と秘密入力の消去を維持する。履歴保存や会話本文への転記は追加しない。この保持境界は現在の通常ターンに限り、Goal・依頼完了を含む本設計は別場の議論とU06・U07に残す。

設定の全項目・タブ、4段階表示、プレビュー方式、OS別取得・フォールバック、機器表示名による選択は維持する。取得隔離、終了期限・解放確認、共有画像の独立した読取、古い要求の失効、回答の二重送信防止、原稿・閲覧位置の保持も削減のために壊さない。

## 7. 設計メモ・関連文書

### 状態管理の棚卸し

以下は現行所有元を静的に確認した結果とM0の判断である。属性の数を目的に削るのではなく、新契約に必要な状態かをM1で確認する。

| 現行の状態・経路 | 判断と整理後の責務 |
|---|---|
| `SettingsDialog._saved_device`／`_selected_device`／`_edited_device`、`capture_target`、`preserve_target` | 一時停止と暗黙／明示選択の区別による三重管理を撤去。設定基準値とフォーム編集値で足りる。実状態は取得側が所有 |
| `ApplicationShell._menu_target_after_save`とdirtyな画面への同期 | モーダル化で同時編集経路をなくす。メニュー専用の選択値・同期予約は不要 |
| `_applying_settings`／`_close_after_apply`／`_finish_settings_apply()`の初回フレーム待ち | 保存処理までの待ちへ縮小。提出済み設定と保存後に閉じるかの情報は一件のI/O文脈に限定し、取得状態と組み合わせて保持しない |
| `_capture_after_save`と`VideoController._replacement`、`_pending_connection` | 保存前の提出値と解放後に開始する反映先は寿命が違う。必要な一件ずつだけ所有し、Shellに別の接続予定や停止後再開用機器を残さない |
| `_refresh_on_open`／`_refresh_menu_on_open`／`_refresh_after_disconnect` | 開いた時に列挙可能なら実行し、不可なら既存候補と明示更新を使う。自動列挙の予約を撤去 |
| `pending`のdialog／reloadと終了待ち取消し | ダイアログは即時に閉じ、再読込を撤去。アプリ終了要求・未保存確認・サービス終了確認だけを残す |

必要な状態は、最後の成功設定、開いているフォームの編集値、実行中I/Oの入力一件、取得中資源と最新の反映先、要求・フレームの世代、解放確認、エラー詳細である。dirtyやボタン可否はそこから求め、同じ意味のboolを各層に保存しない。接続中／停止中などは資源の実態であり、表示を減らすために消してはならない。

根拠は[Shell](../../../src/gigas/app/shell.py)、[設定画面](../../../src/gigas/ui/settings_dialog.py)、[映像制御](../../../src/gigas/app/video.py)、[メニュー](../../../src/gigas/ui/main_window.py)、[設定適用試験](../../../tests/integration/test_settings_apply_contract.py)、[OK試験](../../../tests/integration/test_settings_accept.py)。現行試験の「保存機器を残す停止」「停止中の無変更OKでは接続しない」「OKは初回フレームを待つ」は新契約では維持しない。

[NyXの調査記録](../../complete/unit_026/SETTINGS_AND_STATUS_REDESIGN.md)と今回の手元ソース読取では、OKも適用処理を呼んでから閉じる。Gigasの保存失敗・非同期機器処理の契約は別途守り、同期処理をそのまま移植しない。既存complete仕様は過去の受入記録として保持し、本書の変更を実装済みと書き換えない。

工程の入口は[実装計画](../../initial/05-implementation.md)、UIの製品要求は[設計概要](../../initial/01-overview.md)、初期の画面境界は[U01の画面仕様](../../complete/unit_004/APPLICATION_SHELL.md)を参照する。
