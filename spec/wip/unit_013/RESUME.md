# U08 Project・会話管理の統合と再接続 親仕様

## 1. 目的・状態・起点

Project・会話・Goal・自動記憶の管理をCodex app-serverへ委譲し、新規プレイと既存会話からの継続をGIGASの画面から扱えるようにする。GIGASはゲームI/Oと人間の介入を担い、既存会話を現在の機器・MCP・記録先へ接続する。独自ログから会話やGoalを復元する工程にはしない。

状態: **wip（M0の要求・設計整理に着手）**。2026-11-14の要求整理を反映し、[M0 責務・保存境界の設計](../unit_068/MANAGEMENT_STORAGE_DESIGN.md)を開始した。境界確定・初期設計のリライトは進行中であり、製品実装・受入は未着手である。親工程はM0の完了だけでは完了しない。

| 起点 | 内容 | 参照 |
|---|---|---|
| 当初計画 | U06の同一セッション再開を基に、再起動後の継続を追加する | [実装計画](../../initial/05-implementation.md) |
| 2026-11-14の合意 | 管理機能はapp-serverへ寄せ、会話の持ち出し用複製を廃止する。攻略補助は実プレイで不足を観測してから検討する | 本書の責務・工程・未決事項 |
| 作業規約 | 親仕様の整理、方式調査、製品実装、実接続・実機検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面は、Project内で新しい依頼を始める、既存の会話を閲覧する、アプリ再起動後に同じ会話の続きを任せる、同じ攻略資料を使って新しい会話を始めることである。依頼の規模や長期目標と途中指示の関係はCodexに任せ、GIGAS独自の目標階層を設けない。

## 2. 現行設計との差分・前提

現行の[保存・記憶設計](../../initial/04-agent-memory.md)と製品実装には、独自の`project.json`、公開会話・Goal関連の記録、`guide.md`・`memory/current.md`の生成、独自記録先を前提にした選択処理がある。本工程でこれらを見直す。会話をCodex以外へ持ち出すための複製要件は撤回し、GIGAS独自ログによる会話・Goal再構成と固定メモからの専用コールドスタートは採用しない。

本書は改訂後の到達点を定める。`spec/initial`は今回一括更新せず、M0で未決事項を確定して関連設計をリライトする。採用予定の契約と現行実装を区別し、文書更新を製品の移行完了としない。完了済み仕様は過去の実装・検証記録として保持する。

[U06](../../complete/unit_011/GOAL_EXECUTION.md)、[会話実行](../../complete/unit_061/CONVERSATION_EXECUTION_MODEL.md)、[Goal操作](../../complete/unit_062/GOAL_EXECUTION_MODEL.md)、[契約整理](../../complete/unit_054/KISS_SIMPLIFICATION.md)の成果を前提とする。通常送信・追加指示の配送、共通停止、機器入力の取消し・解除は共用する。共通停止はactiveなGoalを目的を保持して休止し、Goal削除は現在動作の停止と分ける。同一セッションの停止後に独立した再受付状態を追加しない。U07は初期版対象外であり、着手・受入条件に含めない。

事前調査は、採用版`0.167.0`の公開schema・実装と隔離homeでの限定的な接続試行を材料とする。Projectの永続化、所属threadの一覧・read/resume、Project削除後のthread保持を試行したが、モデルによる攻略再開・自動記憶生成・Codexアプリとの相互運用を検証したものではない。M0では根拠・再現手順を子仕様へ記録し、採用する製品経路で確認する。外部契約は[08](../../initial/08-sdk-compatibility.md)の採用版と照合し、最新Web文書だけで成立済みとしない。

## 3. 責務分担と保存方針

### 3.1 合意した責務

| 所有者 | 責務 | GIGAS側で重複させないもの |
|---|---|---|
| app-server | Projectの識別・情報・会話所属、threadの履歴と永続化、Goal・継続実行、自動記憶 | 独自Project管理の正本、会話の持ち出し用複製、ログからのGoal復元、独自の自動記憶整理 |
| Codex・利用者 | 依頼の解釈・計画・攻略判断、攻略資料の内容・構成・更新 | GIGASによる長期目標と途中指示の関係管理、固定の攻略手順・記憶様式 |
| GIGAS | 映像取得、観測、入力実行と結果報告、停止・解除、機器接続、ゲームMCP、対話・介入UI | ゲーム内成否の独自推定、停滞推定による自動再投入 |
| GIGASの接続処理 | 公開APIによる選択・表示、使用するthread・作業場所・権限と現在の機器・MCP・記録先の接続 | 表示用状態や前回選択を正本とする会話・Goalの復活 |

Projectは攻略資料の共有単位とし、プロジェクト単位の主な作業フォルダーに対応させる。同じProjectに属する複数の会話が資料を使い、一つの依頼・Goal・会話をProjectと同一視しない。ゲームのセーブデータを保存・復元する単位でもない。

### 3.2 保存する内容と形式

| 保存領域 | 内容・用途 | 形式の方針 |
|---|---|---|
| Codex管理領域 | Project・会話・Goal・自動記憶 | app-serverに任せる。内部DB・rolloutの直接編集を製品経路にしない |
| Projectの作業フォルダー | 攻略メモ、地図、捕獲一覧、手順、利用者の資料など | Codex・利用者が必要に応じて作る。固定ファイル名・見出し・分類を製品の動作条件にしない |
| GIGASのゲームI/O記録 | 入力要求と結果、観測時刻・ID・画像との対応 | 機械処理する項目・単位・識別・関連付けを定める。`events.jsonl`と`observations/<observation-id>.png`を候補とし詳細はM0で確定する |
| GIGASの設定・診断 | 機器・観測・UI設定、前回選択、接続・通信・保存の診断情報 | 設定と診断を攻略資料から分け、資格情報やMCP認証値を記録へ複製しない |

概念上の分離は次のとおりとする。実ディレクトリ名・配置は未確定である。

```text
Codex管理領域（共用home／専用homeは未決）
  Project・会話・Goal・自動記憶
Projectごとの作業フォルダー
  Codex・利用者が編集する攻略資料
GIGASが管理する保存先
  ゲームI/O記録・設定・診断
  （ゲームI/O記録をProject配下に置くかは未決）
```

自動記憶は、現在状態を即時に保存する攻略資料の代替とはしない。GIGASが空の現状メモや索引を生成する方式は撤去対象とし、必要な共通指示と記録参照の案内を残す。攻略資料の規約はプロジェクト指示・SkillsなどCodex標準の拡張手段で後から追加できるようにする。指示による形式指定と機械的な検証は別であり、独自プラグイン基盤や攻略資料validatorは先行実装しない。

### 3.3 記録の保証と用途

入力処理の完了とゲーム内の目的達成は別である。GIGASは取得・実行した事実を記録し、画面からの成否判断はCodexへ任せる。応答と保存の成否は分け、非同期保存による欠損の可能性を隠さない。

ゲームI/O記録は過去画像の参照・操作結果の確認・障害調査に使い、会話・Goal・ゲーム状態の復元用正本にはしない。過去操作を再送せず、履歴全体の正常性を攻略再開の一律条件にしない。既存記録を無断で切り詰めたり、欠損を成功扱いで補ったりしない。破損時の新規記録先と過去記録の保全方法はM0で決める。

操作列の保存だけでは同じゲーム結果の再現を保証しない。通常利用で自動取得する事実と、比較評価用の開始条件・モデル設定・介入・到達点の記録を分ける。評価のために通常プレイへ細かな報告や固定の思考手順を課さない。バックアップ対象には会話・作業資料との関係も含めて検討し、ゲームI/O記録だけで全体を復元できるとは扱わない。

## 4. 対象範囲・対象外

対象は責務・保存境界と初期設計の改訂、Project・会話選択の公開APIへの移行、重複管理・会話複製・固定記憶入口の撤去、ゲームI/O記録の整理、新規開始と既存会話への再接続、指示・Skillsの読込範囲、GUIから実機までの受入である。既存資材の引継ぎ範囲はM0で限定する。

対象外は、ゲームセーブの復元、過去操作の再生、自動再接続・再試行・利用枠回復後の自動開始、独自の会話再構成・記憶整理、U06の共通停止の再実装、独自プラグイン基盤と攻略Skillsの作成である。地図生成・監督エージェントなどの攻略補助、数時間の攻略性能評価は先行追加せず、実プレイの観測から後続作業を選ぶ。汎用移行機構・同期基盤・バックアップ製品の実装を本工程へ含めない。

## 5. M0で確定する未決事項

以下はすべてM0担当が調査・決定を記録し、依存する実装の開始前、遅くともM0完了時までに解消する。未成立の公開経路を想像した内部データ操作で補わず、必要なら対象範囲と受入条件を再協議する。

| 論点 | 決める内容・必要な確認 |
|---|---|
| homeとCodexアプリとの関係 | 主な操作はGIGAS内で完結し、外部Codexとは必要時に作業フォルダーを共有する。同じProject・会話の管理や相互実行の連携は必須にしない。共用維持／専用化は未決とし、認証・設定・自動記憶の共有範囲と版の共存から判断する。homeの分離をsandboxの隔離と同一視しない |
| Projectと作業場所 | 主な攻略フォルダーの対応、作成・既存フォルダー選択、Project未選択の会話、rootsとthreadのcwd・権限の設定を決める。未選択時に独自Projectを暗黙生成する前提を置かない |
| 記録の配置・参照・寿命 | Project配下／アプリデータ配下、thread・観測・入力との対応、再接続・新規会話・別会話からの参照を決める。Project削除、会話アーカイブ、記録削除を区別し、保持・欠損・破損・バックアップ対象を定める。自動削除を既定にしない |
| 記録形式 | 自動取得する事実、schema・単位・ID・時刻、画像と入力の関連付け、通常記録と評価用記録の境界を決める。用途を説明できない予約項目を追加しない |
| 自動記憶・指示・Skills | 採用版の有効化・生成・参照条件と共有範囲、プロジェクト指示・Skillsの読込方法を確認する。現行の読込抑制を点検し、意図しない開発用指示の混入を避ける。自動記憶の即時性・完全性を再開条件にしない |
| 再接続と明示開始 | readとresume、activeなGoalのresume時挙動、最新MCP URL・認証値の再設定、古い要求の失効、現在画面の確認を検証する。「会話を開くだけではゲームを操作しない」を実現する公開経路を決める |
| 既存資材の引継ぎ | コードの置換とデータ移行を区別し、旧Project・会話・資料・画像の必要な引継ぎ範囲を決める。既存資材を無断変換・削除しない。旧データ保全と旧実装の維持を混同しない |

## 7. 振る舞い仕様・TDD Test Listの受入観点

| 観点 | 工程全体で確認する振る舞い |
|---|---|
| 管理の正本 | Project・会話所属・Goalは公開APIの結果を表示する。GIGASの保存ログや前回選択から別の正本を作らない |
| 新規開始と資料 | 同じProjectの新規会話で共通の作業資料を使える。既存資料を初期化せず、特定の攻略資料形式を開始条件にしない |
| 自動記憶 | M0で選定した設定が製品経路に反映され、対象の会話がapp-serverの記憶生成・参照の仕組みを利用できる。有効化・生成対象・参照経路を確認するが、毎回の即時生成や記憶の完全性は保証せず、生成待ちを開始・再開条件にしない |
| 明示的実行 | アプリ起動・Project選択・履歴閲覧だけではゲーム操作を始めない。通常送信・明示的Goal操作で開始する。再接続後もこの境界を守る |
| 再接続 | 保持されたthread・Goalへ現在のMCPと機器を接続し、現在画面を確認して継続する。削除済みGoalを復活させず、使えない会話からの新規開始は利用者の明示操作とする |
| 停止と失敗 | 共通停止・解除を維持し、古い要求や未完操作を再送しない。結果不明を成功と表示せず、復帰失敗を独自の自動修復へ変換しない |
| 記録と権限 | 取得画像・入力結果の対応を保ち、欠損や保存失敗を実行結果と分ける。作業資料の書込と原記録の参照範囲を、実際の公開実行設定で確認する |

親では受入観点のみを定める。詳細なTDD項目・故障注入点は各子仕様が所有する。既存の[検証観点](../../initial/07-verification.md)との対応はM0で更新する。文書の見出し・状態語・固定文言を製品テストにしない。
