# New Nintendo 3DS XL の映像取得（ponkan-python）

Windows の GIGAS で、対応キャプチャ基板を搭載した New Nintendo 3DS XL 1台の 2D 映像をプレビューし、同じ取得元を Codex の観測と記録に使う。初版の合意仕様と受入条件を示す。Windows 実機での確認範囲は末尾に記載する。

## 取得元の選択と保存

「設定 → I/O」の映像取得元と「接続 → 映像」の両方に、対応基板を1台検出した場合、またはその取得元で映像を取得中の場合に「New Nintendo 3DS XL (ponkan)」を選択肢として表示する。一覧更新は USB 記述子の照会までとし、映像取得は接続操作で開始する。取得中の 3DS がなく、検出も0台のときは候補から除き、保存・編集中の取得元なら「未検出」と表示して値を保持する。複数台やドライバー利用不可は診断で理由を示し、カメラ候補は選択できる。

設定ダイアログと接続メニューは既存の保存・適用処理を共用する。従来の設定ファイルにあるカメラ識別子と未選択値はそのまま読み込めるようにする。起動時には保存済みの取得元へ一度接続する。切替時は保存に成功し、旧接続の終了を確認してから新しい取得元を開く。接続失敗や抜去の後も保存値を保持し、再選択または「適用」で再試行できる。「未接続」の適用で取得を終える。[既存の設定と再試行](../../../docs/guides/settings.md#映像の選択と適用)

| ponkan 選択時の項目 | 振る舞い |
|---|---|
| 取得FPS・取得解像度 | カメラ用の要求値なので編集を無効にする。保存値を保持し、カメラに戻したときに再利用する |
| 表示FPS・プレビュー方式 | 既存の表示処理に適用する |
| 観測解像度 | 既存の観測処理に適用する。観測解像度だけの変更で取得を再開しない |

## 一覧検索と映像取得の責務

設定画面と映像メニューを開いたとき、または「一覧更新」を押したときに候補を非同期検索する。検索中も機器欄とメニューの配置を保ち、検索の失敗時だけ「列挙失敗」を表示する。カメラ・3DS とも、映像取得中は検索1回だけを別の子プロセスで実行できる。取得プロセスは接続直前の機器確認、open・read・close、フレームの公開を所有する。検索プロセスは候補と診断を返して終了する。検索失敗や期限切れでもプレビューと MCP 観測は同じ接続世代の画像を読み続ける。

一覧には検索結果と、実際に取得中の機器を識別子ごとに一度ずつ表示する。検索結果に含まれない使用中の 3DS も通常名で残す。切断すると使用中としての表示を解除し、以降の検索結果で候補を決める。検索中に映像を切り替えた場合、旧接続の検索結果は新しい一覧に反映しない。保存値と設定画面の未適用の選択は、検索結果で書き換えない。

## 接続と停止

ponkan への接続を要求したときに、取得子プロセスで `list_capture_devices(profile="n3dsxl", backend="auto")` を呼ぶ。対応候補が1台のときだけ `open_capture()` へ進む。取得方式は `auto` に固定し、Windows では `d3xx-native` を使う。対応候補の判定は ponkan に任せる。

ドライバーを利用できないと判明した場合、対応候補が0台の場合、複数台の場合を既存の映像診断で区別する。利用者がそれぞれドライバーを確認する、ボードを接続する、対象の1台だけを接続する、という復旧操作を選べるようにする。列挙や open 自体が失敗した場合はその失敗理由を残す。公開 API は指定した個体を開けず、open 内で再列挙した先頭候補を開くため、接続操作中はボード構成を変えないことを前提とする。[上流の列挙 API](https://github.com/niart120/ponkan-python/blob/cdff5d59bc4e08cefa495b8c67c8eb60aeb0c528/docs/api.md#device-discovery)・[接続処理](https://github.com/niart120/ponkan-python/blob/cdff5d59bc4e08cefa495b8c67c8eb60aeb0c528/src/ponkan/capture.py#L366-L387)

同じ子プロセスが reader を開き、有限時間の読み取りと解放を行う。`read()` が期限内に画像を取得できず `None` を返した場合は新しい Frame を発行せず、停止要求を確認して読み取りを続ける。最初の実画像で接続成功とし、画像の途絶は既存の開始期限・フレーム待機期限で判定する。切断・失敗時は最新画像を失効させる。終了時は既存の監視で通常解放・強制終了・終了未確認を区別する。[GIGAS の映像取得 API](../../../docs/design/interfaces/video-api.md)

## 画像と実装の境界

ponkan から `BOTH_VERTICAL`、BGR、uint8 の画像を受け取る。元の Frame は幅400×高さ480。上段に400×240の上画面、下段に320×240の下画面を中央配置する。下画面の左上は元画像の (40, 240) にある。プレビュー用の16:9の余白は元画像に追加しない。プレビューの拡縮と観測 PNG の出力寸法は、それぞれの既存設定に従う。入力のタッチ座標は従来どおり下画面内の x=0〜319、y=0〜239 を使う。[上流の画像仕様](https://github.com/niart120/ponkan-python/blob/cdff5d59bc4e08cefa495b8c67c8eb60aeb0c528/docs/api.md#frames)・[GIGAS の入力 API](../../../docs/design/interfaces/input-api.md)

| 対象 | 初版で使う設計・必要な変更 |
|---|---|
| NyXPy から取り入れる部分 | 固定の取得元を選び、薄いアダプターで ponkan の公開 API を呼んで BGR 画像を取得する。[NyXPy の実装](https://github.com/niart120/Project_NyX/blob/648f860e5afd582f80aa58645570a16bfc68a393/src/nyxpy/framework/core/hardware/ponkan_capture.py#L144-L175) |
| GIGAS で追加する部分 | 設定・メニューでの選択と保存、取得子プロセス内での候補数確認、ponkan 固有の open・read・close と診断への変換。OpenCV の機器番号・要求 FPS／寸法・代替方式の試行はカメラ経路に置く |
| GIGAS で共用する部分 | 取得子プロセスの監視、共有メモリ、接続世代・連番・ホスト取得時刻を持つ不変の Frame。最新画像を既存の読み手からプレビューと MCP 観測へ渡し、同じ観測画像を PNG に保存する。[映像とゲーム操作の経路](../../../docs/architecture.md#映像とゲーム操作の経路) |

## 配布の前提と受入

Windows の通常依存に、初回読み取り前の解放を修正した [ponkan-python 0.2.1](https://pypi.org/project/ponkan-python/0.2.1/) を含める。調査した 0.2.0 では、open 直後に一度も read せず close すると、未開始状態の `StreamingEngine.stop()` がバックエンド解放前に戻る。これは模擬バックエンドで再現した。この経路の修正と回帰テストは [ponkan-python PR #37](https://github.com/niart120/ponkan-python/pull/37) に含まれる。[0.2.0 の終了処理](https://github.com/niart120/ponkan-python/blob/cdff5d59bc4e08cefa495b8c67c8eb60aeb0c528/src/ponkan/streaming/engine.py#L81-L98)

| 確認環境 | 完成を判断する条件 |
|---|---|
| 配布・CI | 採用する公開版を含めて GIGAS の宣言済み Python 範囲で依存を解決し、既存の Windows CI（Python 3.12・3.13）を通す |
| 模擬機器・設定 | 既存設定の読込、ponkan 選択の保存・復元、カメラとの往復、項目の有効状態と保存値を確認する。0台・複数台・ドライバー利用不可では open に進まず、失敗を区別できる |
| 模擬機器・取得 | 単発の読み取り期限切れ後は次の実画像を受け取れ、画像の途絶時は監視期限で失敗する。open 成功後・初回 read 前に取消しを発生させ、取得済み reader の close とバックエンドの解放を確認する。取消し後に旧世代の画像が公開されないことも確認する |
| 取得中の一覧更新 | 使用中の取得元が検索に現れなくても候補に一つだけ残り、別の取得元を選べる。成功時・失敗時とも取得世代を維持して連番が進み、切断後は使用中だったことを理由に候補へ加えない |
| Windows 実機1台 | 一覧を更新し、検出された ponkan を選択・適用してプレビューできることを確認する。実機の映像で上下画面の向き・配置・色を目視する |
| 実機での MCP 観測・記録 | 同じ観測 ID で Codex が受け取った画像と保存 PNG を対応付け、バイト単位で一致することを確認する。プレイ時の記録を使用できる |

## 実機で確認した範囲

利用者は候補表示の変更前に「New スーパーマリオブラザーズ」の「ルイージの絵合わせポーカー」を実機でプレイした。2026-11-20 のプレイ記録から、上段にルイージ、下段に手札が表示され、文字の向きと赤・緑などの色を保存画像で確認した。

MCP 観測と保存 PNG の照合は受入済み。プレイ中の `observe` 12件と `act_and_observe` 7件を観測 ID で保存記録に対応付け、Codex が受け取った画像と保存 PNG が全19件でバイト単位で一致した。元フレームは400×480、返却画像と保存 PNG は300×360だった。

2026-11-20 に Windows で独立した検索プロセスを各3回動かした。Elite Go GC313Pro は取得中も列挙できた。3DS は映像の連番が進む間も検索から消えた。D3XX は取得前と解放後には VID/PID `0403:601e` と製品名 `N3DSXL.2` を返し、取得中は `0000:0000` で製品名が空だった。

実装後の設定画面で実機の 3DS を選択・適用し、「一覧更新」を2回実行した。「接続 → 映像」を開いたときの自動検索も含め、全3回で接続世代を維持してフレーム連番が進み、使用中の 3DS は通常名で1件だけ表示された。「未接続」への切替で使用中としての補完が外れ、USB 接続を保ったまま再検索すると 3DS が候補に戻った。Elite Go GC313Pro の取得中にも同じ2画面から計3回検索し、カメラが重複せずフレーム連番が進むことを確認した。基板0台の候補非表示は模擬機器で確認した。
