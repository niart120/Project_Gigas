# UI改善の画面・実機検証

状態: 検証を進行中。個々の確認結果を記録し、未実施項目を分ける。[実装仕様](UI_UX_REFINEMENT.md)の受入記録。

## 実機の映像適用

2026-11-11、`2ed623d`で実施。Windows、Python 3.12.10、Qt 6.12.0。実キャプチャーはLive Gamer 4K 2.1系（VID07CA/PID0575、DirectShow表示名`USB Video Device`）。機器パスは今回の自動列挙から得た値を使用した。接続中のゲーム画面を受信し、描画画像でGAME FREAKロゴを目視した。

`uv run python -X utf8 tmp/uiux-refinement/hardware_apply.py`により実サービス・実Qtの設定ウィジェットを操作した。物理機器を使っているが、Qt描画はoffscreenであり、Windowsのネイティブ画面操作とは区別する。描画用プロセスだけMeiryo UI 9ptを指定し、製品フォントは変更していない。設定ファイルも一時ディレクトリ内へ隔離した。

| 操作・観測 | 結果 |
|---|---|
| 空の設定→設定画面を開く | 一覧を自動取得し、機器の表示名で選択できた |
| 機器選択→適用 | 保存後に接続し、1920×1080の最初のフレームを取得した |
| 取得中に設定を閉じて再表示 | 再列挙・再接続せず映像を継続した |
| 表示FPS 30→15、表示サイズHD→FullHDを適用 | 取得世代1を維持。約6秒間で連番363、プレビュー121更新。別読み手が保持する画像も不変 |
| 取得FPS 60→30→60を適用 | 世代1→2→3。各旧世代の正常解放を確認した後、新世代を接続した |
| 設定内で切断 | 映像を無効化し、正常解放後に一覧を1回更新した |
| 保存済み機器へ再接続 | 世代4の最初のフレームと継続更新を確認した |
| アプリ終了 | 全体約29.94秒。取得サービス停止、設定ワーカー/Codexサービスの終了、子プロセス残存なし、`cleanup=graceful`を確認した |

30 FPS要求時の機器報告は30.00003 FPS、約3秒の観測では実測28.69 FPS。60 FPS要求時の報告は60.00024 FPS、実測58.69 FPSだった。要求値と機器報告と実測値を区別し、短時間の結果を長時間性能の保証にはしない。20ms間隔の観測で子プロセスは最大1つだった。

この確認で、独立した読み手が保持する過去フレームはプレビューを停止させなかった。U04のMCP接続・画像保存や、U05のゲーム入力を実装・検証したことは意味しない。

## 通知の描画

T07の通知描画は実施済み。模擬イベントを実Qtへ投入し、Meiryo UI 9pt、作業領域800×600と1920×1080で通知・詳細・長い終了待ちの計6画面を確認した。外枠はそれぞれ800×451と1916×1080を維持。小画面で現在状態の幅67px、モデル名201px、中断80×24pxを確保し、長い値は省略、診断全文は専用の詳細領域で選択できた。コピー中の新着通知で本文が変わらないことは回帰試験でも確認した。主画面に残る旧設定行・接続ボタンはT08で変更するため、これを最終配置の受入とは扱わない。

## メニューの描画

T08では合成画像・模擬Codexイベントを使い、主画面と開いた映像メニューをHD／FullHD相当で描画した。外枠800×451、1916×1080を維持。旧設定ボタン行・映像上部の操作と状態がなく、メニュー・ステータスバーへ移ったことを確認した。長い同名候補と`&`を含むメニューは353×172pxへ収まり、省略しても末尾の(1)/(2)、保存済みの選択印を判読できた。これは合成描画の結果であり、機器名や画像を実機の観測結果とは扱わない。
