# U05 操作と停止 親仕様

## 1. 目的・状態・起点

Codexの通常ターンから有限の操作列を実機へ送り、解除後の観測を返す。利用者の停止をCodex応答待ちにせず、記録と入力許可を含む一連の経路として確認する。

状態: **wip（M0調査・設計完了、製品実装未着手）**。2026-11-12に[最初の子仕様unit_036](../../complete/unit_036/INPUT_AND_STOP_DESIGN.md)でNyXPyと現Gigasを調査し、設定・通信・有限列・停止・操作権・事後観測・記録を設計した。採用runtimeの公開経路と実モデルを模擬入力で確認した。シリアル実接続・実機入力は未実施。M0完了だけで本工程をcompleteへ移さない。

|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 利用者が操作依頼を明示的に開始する。Codexがact_and_observeを呼び、操作後の画面を確認する。途中でGUIから停止すると後続入力が実行されない。

## 2. 前提と着手条件

GUIの依頼入力・停止導線は[実装整理](../../complete/unit_027/IMPLEMENTATION_SIMPLIFICATION.md)と採用済みの[主画面とメッセージ操作](../../initial/10-ui-interaction.md)に従う。M0で設定モーダル表示中を含む通常ターンの即時停止の入口を具体化し、M2で物理入力と結合確認する。映像機器の「未接続」による取得終了と、推論中断・物理入力の停止は別の責務。U06 M1のUI置換、M2のGoal保持／破棄・同一セッション再開へ共通停止処理を引き継ぐ。本工程に仮のGoal状態や終了専用経路を作らず、U06の画面完成を実機停止の前提にしない。

[U04](../../complete/unit_009/RECORDED_OBSERVATION.md)の観測・記録・MCP、[U02](../../complete/unit_007/CODEX_CONNECTION.md)の通常ターン・要求応答・中断を利用する。入力を公開する前にMCP接続と実行世代の対応・旧要求失効が採用版で成立することを確認する。U01のポート文字列保存は入力接続の成立を意味しない。

2026-11-12のU04 M0では、`observe`は取得中の最新キャッシュを一度のsnapshotで確定する設計へ変更した。U04は要求後の新フレーム待機APIを提供しない。本工程の`act_and_observe`は最後の解除・待機完了後に取得した画像を返す契約を維持し、M0で境界時刻・待機期限・停止・世代変更の扱いと実装方式を決め、M1で実装する。U04の保存・画像応答形式を共用することと、操作後の鮮度条件が完成していることを混同しない。

U02完了後レビューR01は[設定障害時の停止修正](../../complete/unit_019/SESSION_STOP_AVAILABILITY.md)で修正・Qt回帰確認済み。実機入力を公開する前には、設定障害中も物理入力を即時停止できることを本工程で結合確認する。

親仕様は工程全体の受入条件を所有する。現在はM0完了・製品実装前の`spec/wip`である。M1/M2の子仕様は未作成で、着手時に必要な一つだけを作る。M1の着手条件と未確認事項の確認時期は[M0の10節](../../complete/unit_036/INPUT_AND_STOP_DESIGN.md)を正本とする。現コード・依存版を照合し、既存試験の改訂先を決めて着手する。実機条件が未確認でも内部実装は進められるが、該当protocolの実機受入を省略しない。今回はM0で止める。

## 3. 対象範囲・対象外

対象: 実デバイスとシリアル仕様の選定、操作列の全体検査、有限時間の実行・待機・取消し・解除、一つの入力所有者、依頼・実行・操作の記録、act_and_observe、GUIの開始・即時停止、通常ターンとの結合を扱う。

対象外: Goalの自動継続、計画的なプレイ終了、停止後の攻略再開、記憶整理、Bluetooth、第三の操作専用MCPツール、実機へのexactly-once保証は含めない。

## 5. M0の調査・設計成果

詳細と根拠は[unit_036](../../complete/unit_036/INPUT_AND_STOP_DESIGN.md)に集約する。以下は採用した設計であり、製品実装済みの一覧ではない。

| 対象 | 採用した判断 | 残る受入 |
|---|---|---|
| 機器・設定 | CH552/PokeCon/3DS S2/T3 New Firmwareの3形式。protocol別baud定義をUI・保存・接続で共用。一つのSettingsをOK／適用で保存して接続先へ反映。「未接続」の適用で切断。操作中の変更は旧列の停止・解除・close後に切替 | 各ファーム・baud・open時reset・実neutralを実機で確認 |
| 実行・停止 | 完全入力状態のpress/wait、正の整数msからなる有限配列。入力時間・要素数・合計時間の固定上限は設けない。単一所有者・シリアル専用worker。権限判定は要求受付に集約し、実行中は操作の取消しで止める。停止は保存やCodex応答を待たず、解除は終了処理で扱う | 列検査、部分write、押下/待機/保存/モーダル中の停止、終了 |
| 事後画像 | read開始単調時計をFrameへ追加し、同じ取得世代かつ最終解除・待機完了後にreadを開始した画像を5秒以内に選ぶ。U04の最新キャッシュ観測は維持 | 搬送・境界競合・取得変更、実映像の反映遅延 |
| 操作権・MCP | run固定Grantと新endpointを対応。停止・通常turn終端で失効。次の明示送信は適用中protocol・対応入力を示す新MCPを公開し、unsubscribe→同ID resumeでCodex側を再読込。副作用注釈を正しく付け、当該toolだけapproval_mode=approve | 模擬公開経路と実モデル2turnは確認済み。製品の停止・通知・接続への結合はM2 |
| 記録 | request/run/operationに入力列・実行結果・観測IDを対応付ける。接続情報は通常記録に含めない。開始行は入力前に保存成功必須、結果と画像は非同期。同じwriterへの記録を順序化し停止を待たせない | 記録失敗、操作結果不明、観測ID対応、通常終了drain |

## 7. 振る舞い仕様・TDD Test Listの受入観点

| 観点 | 工程全体で確認する振る舞い | 主な検証 |
|---|---|---|
| 入力前の拒否 | 無効列・無効世代・BUSY・開始記録失敗では物理入力を送らない | T01・T03・T09 |
| 実行と観測 | 順序・押下・解除・待機を守り、最後の解除・待機完了後に取得した画像の確定・符号化まで別の操作列を実行しない。操作完了前のキャッシュを事後画像にしない | T01・T04・T05 |
| 途中停止 | 待機や押下中の停止で残りを破棄し、取消し中も解除処理を行う。解除送出と実機の解除確認を区別する | T02・T15、単体・結合・実機 |
| 旧処理と人間の要求 | 停止後の古いMCP要求・active通知・回答で入力を再許可しない。回答待ちの新規入力を保留する | T03・T07・T15 |
| 失敗と記録 | 入力後の画像・保存・通信失敗では実行済みの可能性を残し、自動再送しない。解除送出未確認を停止完了にせず、送出済みも実機解除確認と区別する | T09・T17、結合・実機 |
