# U01 M3 指示リソースと配布物

## 1. 概要

### 1.1 目的と状態

[親仕様](../unit_001/APP_STARTUP.md)のU01完了条件と[07のT20](../../initial/07-verification.md)を、実際にビルドした配布物で確認する。状態は独立設計案、実装未着手。リソース設計は[M0](../../complete/unit_002/ARCHITECTURE_AND_DEPENDENCIES.md)完了後に進められ、最終確認には[M2](../unit_004/APPLICATION_SHELL.md)の起動実装が必要。

### 1.2 起点と利用場面

[04](../../initial/04-agent-memory.md)の共通指示分離と[06](../../initial/06-repository.md)の同梱・読込方針に基づく。利用者がリポジトリを持たない環境へインストールしても、同じ入口で起動し、アプリが必要な共通指示を取得できることを確認する。

## 2. 対象範囲

攻略共通指示の実リソース初版、取得API、wheelとsdistへの同梱、sdist再ビルド、隔離インストール、リポジトリ外の起動・読込、利用手順を対象とする。

## 3. 対象外

Codexへの配送、攻略成功の評価、整理用スレッド、プロジェクト案内の生成、exe凍結、インストーラー、PyPI公開は含めない。ライブラリの配布確認をCodex接続の成功として扱わない。

## 4. 関連文書と責務

promptsは読み取り専用の実行時リソース。個人の設定・ゲームの記憶をここへ保存しない。appは必要な場面で取得し、storageやGUIがリポジトリ相対パスから読む構成にはしない。起動入口と画面の責務はM2に従う。

## 5. 振る舞い仕様

### 5.1 同梱する内容

`src/gigas/prompts/play.md`に、実画面を観測して操作すること、観測と操作列の意味、推測と確認済み事実の区別、質問・停止の扱い、記憶と画面が違う場合に確認することを書く。ゲーム固有の攻略順、認証情報、個人の絶対パス、開発用AGENTS.mdを含めない。

実際のツール引数・保存先はU02/U05/U06で決まるため、未実装API名や未置換の仮変数を指示へ入れない。U01の文書は現時点で意味のある共通指示とし、具体情報の配送時に改めて整合を確認する。内容の妥当性は文書レビューで確認し、自然言語の固定一致テストを作らない。

### 5.2 取得とエラー

標準のimportlib.resources.filesを使い、UTF-8で読み込む。呼出し元のcwdとソースtreeの有無に依存させない。ファイルがない、空または空白だけ、デコードできない場合は理由付きエラーとする。代替の仮指示を成功として返さない。

import時の読込はしない。設定画面は指示を使わないため、指示欠落だけで起動禁止にはしない。ただし配布物の検査は不合格。攻略開始側ではU06が指示取得成功を開始条件にする。

### 5.3 配布物の検査

| 段階 | 観測する結果 |
|---|---|
| wheel作成 | gigas/prompts/play.mdが含まれ、期待したUTF-8内容を持つ |
| sdist作成 | src/gigas/prompts/play.mdと必要なビルド情報が含まれる |
| sdistからwheel再作成 | 同じ実指示を取得できるwheelができる。アーカイブ全体のバイト一致は要求しない |
| 隔離インストール | 編集可能インストールを使わず、import元が隔離環境を指す |
| リポジトリ外からの実行 | リソース読込とgigas/python -m gigasの共通入口が成立する |

uv_buildの既定のモジュール収録を使い、不要なMANIFEST.inや広い包含指定は追加しない。実ファイルが漏れた場合は原因と最小の設定変更を本書へ記録する。インストール後のパッケージを実行中に書き換えない。

確認用の環境・作業ディレクトリはリポジトリ外に置き、PYTHONPATH等で開発ソースへ到達させない。実行したコマンド、絶対パス、配布物名、import元、Python/Qt版を結果へ残す。GUIの保存先は試験用のユーザーデータ領域に限定する。

## 7. 設計メモ

M0ではビルドバックエンドのソースを確認しただけで、GIGASの実指示入り配布物を作っていない。T20達成は本単位の結果で判断する。U02の案内、U08の整理指示の追加時も収録対象を増やして確認する。

## 8. 対象ファイル

`src/gigas/prompts/`、取得・配布物試験、必要ならビルド設定、READMEと詳細利用手順を対象とする。pytest内でネットワークや実アカウントを暗黙に利用しない。配布確認の実行手順は再実行できるスクリプトまたは試験として残す。

## 9. 検証

すべてnot run。コード追加に対応したruff・ty・unit/integration、uv lock --check、uv buildを行う。追加でアーカイブ内容、sdist再ビルド、uvによる隔離インストール、リポジトリ外の実行、Windows可視画面を確認する。単にuv buildが成功しただけでは本単位を完了にしない。docsのリンク・仮テキストとgit diff --checkも確認する。

## 10. 先送り事項

指示の配送と実ツールとの整合はU06、案内と整理用指示はU02/U08。署名・exe・公開配布はU01対象外。利用者向け文書にこれらを実装済みと記載しない。
