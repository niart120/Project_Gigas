# Project GIGAS — 設計文書

**GIGAS — General-purpose Interactive Gaming Agent System（Project GIGAS）** の製品要求・構成・機能契約・実装計画です。WindowsネイティブのPythonアプリから、Codexに実機ゲームの継続攻略を任せます。初期の動作確認対象はSwitch版FRLGですが、ゲーム固有の攻略判断・記憶をアプリ本体へ固定しません。

2026-11-11に工程と文書の役割を改訂しました。U01の起動・グローバル設定・指示資材の配布経路を出発点に、U02以降は各工程の冒頭で必要な調査・設計を行います。保存機能は、そのデータを使う観測・操作・継続・再開・整理と一緒に実装します。工程の計画を記載したことは、外部仕様の成立や製品動作の確認を意味しません。

# 現在地と次の作業

[U01の基準点](../complete/unit_001/APP_STARTUP.md)は、起動・設定保存・最小GUI・設定I/Oの終了処理・指示資材の配布経路です。映像取得、シリアル通信、MCP、Codex接続、サービス用asyncioループ、プロジェクト保存はU01の完了に含みません。設定欄があることを接続・認証・有効値の確認と読み替えません。

現在は[U02の親仕様](../complete/unit_007/CODEX_CONNECTION.md)へ着手しています。[M0調査](../complete/unit_016/CODEX_SDK_SELECTION.md)でSDK 0.167.0の要求保留中に受信が止まる制約を確認し、直接接続への明示承認を受けM1を開始しています。[U03の映像取得](../planned/unit_008/VIDEO_CAPTURE.md)はU01だけを前提とし、SDK接続とは独立して着手できます。依存の詳細と推奨順は05を正本とします。

作業を始める際は、`AGENTS.md`、現在のコード・依存・テスト、planned / wip / completeを確認し、次の作業を一つ選びます。親仕様を先に揃えても、未着手の子仕様や空クラスを一括作成する指示にはなりません。

# 要求・設計・検証の区別

「採用仕様」は製品が満たす要求です。「初期実装設計」はその要求を実装へ落とす具体案で、実装から得た事実に応じて変更できます。「未確認事項」は確認方法・担当・期限を持つ課題で、対応済み機能ではありません。

設計判断済み、実装済み、接続・実機検証済みを分けて記録します。SDKの参照ソースに機能があること、模擬機器の試験が通ること、Windows実機で動くことは別の根拠です。必要な公開経路が成立しない場合は、影響する要件・工程を見直し、非公開APIや二重受信で補いません。
