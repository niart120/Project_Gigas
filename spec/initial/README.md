# Project GIGAS — 設計文書

**GIGAS — General-purpose Interactive Gaming Agent System（Project GIGAS）** の初期実装設計です。WindowsネイティブのPythonアプリから、Codexに実機ゲームの継続攻略を任せます。初期の動作確認対象はSwitch版FRLGですが、ゲーム固有の攻略判断・記憶をアプリ本体へ固定しません。リポジトリ名・Pythonのルートパッケージ名・配布予定名は`gigas`とします。名称と配置は[06-repository.md](06-repository.md)を参照してください。

**設計初版 v1.0 — 2026-11-10。** 本実装へ引き継ぐ仕様・構成・処理フロー・実装順序・確認計画をまとめています。Python SDKの公開機能を主体とし、攻略の継続制御はCodexへ委任します。保存・記憶管理は独立工程U02、共通指示は`src/gigas/prompts/`へ同梱します。設計の確定はアプリの実装完了を意味しません。採用版の選定、SDK接続とWindows実機の動作確認は本実装で行います。

# Codexへ渡して実装を始める

この一式を対象リポジトリの`spec/initial/`へ配置します。本ファイルは設計文書の索引なので、リポジトリ直下の導入用READMEとは分けて置きます。既存リポジトリへ入れる場合は、そのAGENTS.mdと実装・テストを読んでから配置を調整します。

最初の作業候補はU01「アプリ起動とグローバル設定」です。直後の独立工程U02「プロジェクト・記録・記憶管理」で、プロジェクト、記録、画像保存、記憶の退避・復元をまとめて完成させます。現行工程はU01〜U09で、映像取得はU03、Codex接続はU06です。着手する単位の仕様を`spec/wip/unit_001/`から実際の作業順に作成し、実装・試験・結果をそろえて完了記録へ移します。ユーザーの既存変更を保持し、未実装の機能を成功扱いにしません。


# 確定した要求と変更可能な設計

「採用仕様」は製品が満たす要求です。「初期実装設計」はその要求を実装へ落とすための具体案で、実装から得た事実に応じて変更できます。「未確認事項」は確認方法と影響する部品を記録したもので、対応済み機能ではありません。

手戻りをなくすために全体を作り込む方針ではありません。小さな正式実装を完成させ、外部APIやデバイスの制約が判明したら、その境界と必要な呼出し元を修正します。構成図・ファイル名・型の名称だけを守るために、合わなくなった実装を温存しません。

SDK接続にはPython SDKの公開機能を使い、一つの接続実装が通信・要求・通知を管理します。Goalの複数ターン継続、回答・承認待ち中の停止、実行切替時のMCP接続、画像付き応答は採用版で確認する事項です。公開経路で成立しない機能を非公開APIや二重受信で補わず、未対応として記録します。設計の要求、参照ソースの実装、採用リリースでの動作確認を区別します。
