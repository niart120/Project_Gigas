# U06 Goalによる継続と途中介入 親仕様

## 1. 目的・状態・起点

通常ターンで成立した観測・入力をGoalによる継続攻略へ接続し、依頼・記憶・追加指示・公開状態を対応付ける。攻略判断や継続の再投入をアプリ側へ増設しない。

状態: **planned（未着手）**。本書は2026-11-11の工程計画であり、この工程の方式調査・詳細設計・製品実装・実接続検証を完了した記録ではない。初期設計の既存調査は着手時の材料とし、採用版の動作確認と区別する。

| 起点 | 内容 | 参照 |
|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 追加要求 | 2026-11-11。ログイン・接続とモデル・推論レベルの設定を分け、接続後も次ターンの設定を変更できるようにする | [実行設定の契約](../../initial/02-runtime.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 利用者がプロジェクトと依頼を選び、複数ターンの攻略を明示的に開始する。計画を確認し、追加指示や質問への回答を送り、必要なら停止する。接続を維持したまま次ターンのモデル・エフォートを変更できる。依頼完了はターン終了と区別される。

## 2. 前提と着手条件

[実装整理](../../complete/unit_027/IMPLEMENTATION_SIMPLIFICATION.md)を先行し、主画面の見た目とメッセージの導線は整理後の別の議論へ分離する。[ジャーナル](../../dev-journal.md)の未決事項をU02の画面や既存カードで解決済みと扱わない。本工程のM0でその検討結果・未決事項を確認し、Goal・追加指示・質問・承認・認証設定の実際の操作と公開通知へ具体化する。対応GUIの実装前にその範囲の画面案と操作仕様を確定し、M2の「画面結合」だけを画面設計の代わりにしない。

会話表示を拡張するM2では、[レビューR05](../../dev-journal.md)の応答受信による読み返し位置・文字選択の消失を修正し、末尾追従と利用者の閲覧位置を両立させる。R03は本工程の認証・実行設定分離（T21）で扱う。

[U02](../../complete/unit_007/CODEX_CONNECTION.md)の接続・要求応答と、[U05](../unit_010/INPUT_AND_STOP.md)の記録付きゲーム操作・即時停止が前提。Goal操作と複数ターン通知の公開経路が採用版で成立することを、本工程の実行管理を組む前に確認する。

親仕様は工程の受入条件を所有する。着手時に本ディレクトリを`spec/wip`へ移し、最初の子仕様を具体化する。子の番号を先行予約せず、作業仕様を複製しない。必要な公開経路・機器条件が成立しなければ、その条件へ依存する実装は進めず設計判断を更新する。

## 3. 対象範囲・対象外

対象: Goalの開始・継続・休止・完了、依頼・実行・スレッドの対応、公開計画・状態、追加指示の配送、質問・承認待ち、利用制限、案内と記憶入口、共通指示、必要な保存項目・イベント、認証方式の残作業、認証・接続から独立したモデル・エフォート選択を扱う。

対象外: 計画的終了、停止後の攻略再開、別スレッドの記憶整理・復元は後続工程。アプリ独自の攻略計画、毎ターンの再投入、無通知からの停滞診断、自動修復・自動課金切替は行わない。

## 8. 対象ファイル候補

`src/gigas/runtime/codex/`・`app/`・`ui/`・`storage/`・`prompts/`、対応する試験、認証・モデル・利用手順のdocs、必要な依存定義・lock。03の入力意味を変更する場合は関連契約と呼出し元を同じ子仕様で扱う。
