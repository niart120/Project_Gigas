# U06 Goalによる継続と途中介入 親仕様

## 1. 目的・状態・起点

通常ターンで成立した観測・入力をGoalによる継続攻略へ接続し、依頼・記憶・追加指示・公開状態を対応付ける。攻略判断や継続の再投入をアプリ側へ増設しない。

状態: **planned（未着手）**。2026-11-12のUI合意と仕様レビューを工程計画へ反映したが、本工程M0の接続方式調査・詳細設計、製品実装・実接続検証へは未着手。既存のスキーマ確認と画面モックは着手時の材料とし、製品の動作確認と区別する。

| 起点 | 内容 | 参照 |
|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 追加要求 | 2026-11-11。ログイン・接続とモデル・推論レベルの設定を分け、接続後も次ターンの設定を変更できるようにする | [実行設定の契約](../../initial/02-runtime.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 利用者がプロジェクトと依頼を選び、複数ターンの攻略を明示的に開始する。計画を確認し、追加指示や質問への回答を送り、必要なら停止する。接続を維持したまま次ターンのモデル・エフォートを変更できる。依頼完了はターン終了と区別される。

## 2. 前提と着手条件

[実装整理](../../complete/unit_027/IMPLEMENTATION_SIMPLIFICATION.md)後の議論で採用した[主画面とメッセージ操作](../../initial/10-ui-interaction.md)を本工程へ引き継ぐ。右に映像、左に識別可能なGoal・縦リストのPlan・リッチテキストのHistory・共通入力のMessageを置く。目標は固定名のトグル、reasoning表示は設定ダイアログ、一時停止と停止（Goal破棄）は送信の横の別アイコンとする。M0ではこれを前提に[UI-A1〜A5](../../initial/08-sdk-compatibility.md#ui-api-open)を解消し、Goal識別と別アイコンの未確認画面、要求待ち・失敗時の操作を具体化してからGUIを実装する。モックの成功をAPI成立の根拠にしない。

会話表示を置換するM1では、[レビューR05](../../dev-journal.md)から既存Transcriptへ反映された閲覧位置・文字選択の保持をリッチテキスト表示でも維持する。過去の不具合を未修正と決めつけず、現在の実装を確認して変更する。R03は本工程の認証・実行設定分離（T21）で扱う。

[U02](../../complete/unit_007/CODEX_CONNECTION.md)の接続・要求応答と、[U05](../unit_010/INPUT_AND_STOP.md)の記録付きゲーム操作・即時停止が前提。Goal操作と複数ターン通知の公開経路が採用版で成立することを、本工程の実行管理を組む前に確認する。

親仕様は工程の受入条件を所有する。着手時に本ディレクトリを`spec/wip`へ移し、最初の子仕様を具体化する。子の番号を先行予約せず、作業仕様を複製しない。必要な公開経路・機器条件が成立しなければ、その条件へ依存する実装は進めず設計判断を更新する。

## 3. 対象範囲・対象外

対象: Goalの開始・継続・一時停止・同一セッション内の明示的再開・破棄・完了、依頼・実行・スレッドの対応、公開計画・reasoning・activity、共通入力と目標トグル、追加指示の配送、質問・承認待ち、利用制限、案内と記憶入口、共通指示、必要な保存項目・イベント、認証方式の残作業、認証・接続から独立したモデル・エフォート選択を扱う。

対象外: 計画的終了の結合検証、保存参照からの復帰、アプリ・接続の再起動後の再開、新規スレッドでの再構成、別スレッドの記憶整理・復元は後続工程。アプリ独自の攻略計画、毎ターンの再投入、無通知からの停滞診断、自動修復・自動課金切替は行わない。

## 6. 子工程の分割と順序

| 子工程候補 | 開始条件 | 到達点 |
|---|---|---|
| M0 API・操作契約・Qt確認 | U02/U05の成果、10のUI合意、08の形式確認とUI-A1〜A5 | 共通入力・公開表示・Goal保持／再開／破棄、PySide6表示、記憶入口・認証・次ターン設定の契約を確定する。U07の終了専用経路やU08の復帰実装を前提にしない |
| M1 共通対話UI | M0で共通入力と公開表示の経路が成立 | 左右配置、History／Message、質問・承認、公開Plan・reasoning・activityを通常ターンの実通知へ接続する。旧質問入力経路を置換し、閲覧・下書き保持を確認する |
| M2 Goal操作と継続 | M1とM0のGoal経路 | 目標トグル・現在Goalを結合し、継続・介入・完了・一時停止・同一セッション再開・破棄を記録とともに完成させる。通知購読を開始前に用意する |
| M3 設定変更と結合確認 | M2とM0の認証・設定判断 | ログインと独立したモデル・エフォート変更、利用制限、配送競合を確認する。短い実機依頼と実ランタイムで工程全体を検証する |

M1はGoalがない通常ターンでも成立する対話UIとし、仮のGoal表示・成功応答や旧新UIの切替機構は作らない。質問入力の置換時も承認の明示操作は残す。M2は同じ入力・通知・停止経路へGoalを結合し、M3の認証・設定変更をUI置換の変更へ混ぜない。

これは分割方針であり、子仕様・API・全テストの先行作成ではない。調査で変更理由が生じたら本書と影響する初期設計を更新する。
