# U07 計画的なプレイ終了（初期版対象外）

## 1. 目的・状態

状態: **planned・初期版対象外。製品実装・専用受入は未着手**。

区切り・ゲーム内保存・現状メモ更新から終了までを一つの製品機能として保証する計画は、初期版から外す。通常指示で作業を頼むこと、Goalを保持して明示停止すること、保持Goalを再開することは共通の会話機能で扱う。本書は再検討時の範囲と、初期版へ持ち込まない契約を記録する。工程の完了や将来の実装予約を意味しない。

## 2. 振る舞いと責務

| 利用者の操作・出来事 | 初期版設計での扱い |
|---|---|
| 「保存して終えて」などの通常指示 | 本文をそのままturn/startで送る。開始・介入はapp-server、作業順序とゲーム内の区切りはモデルに任せ、Gigasは終了命令として分類しない |
| モデルの作業報告・Goal休止・turn終了 | 公開情報として表示・記録する。それだけで機器入力を中断せず、セーブ成功や全活動の終了を推定しない |
| ユーザーの共通停止 | activeなGoalを保持して休止し、turn中断と操作列の解除・回収を行う。既存のcomplete・制限状態は保つ |
| Goal削除／再開 | 削除は目的の取り下げだけ。再開は目的文を変えずactiveを要求。通常文の「再開して」は特別扱いしない |

共通契約と内部再編は[unit_061](../../complete/unit_061/CONVERSATION_EXECUTION_MODEL.md)・[unit_062](../../complete/unit_062/GOAL_EXECUTION_MODEL.md)を正本とし、その実装・検証結果も両unitで管理する。停止後にGoalを再開する場合も、終了作業の再実行やセーブ状態の復元は保証しない。

## 3. 対象外・撤去する契約

終了専用の状態・Goal・turn・権限・結果schema、自然文による停止意図判定、Goal休止通知からの自動機器停止、端末列挙による全書込み終了保証、セーブ完了の汎用判定は設けない。既存のU07 M0/M1とUI-A6を初期版の必須工程・受入条件から外す。「保存して終えて」を送った結果にGoal休止を要求する試験も作らない。共通経路の検証をU07名義で重複実施しない。

アプリ閉鎖時の資源回収、通常指示・Goal・明示停止の検証は対象外にならない。それぞれの所有仕様で行う。

## 4. 関連仕様・後続依存

[実装計画](../../initial/05-implementation.md)・[検証観点](../../initial/07-verification.md)・[UI](../../initial/10-ui-interaction.md)から専用終了の初期版要件を外す。[U08](../unit_013/RESUME.md)は保存参照・再起動後の復帰、[U10](../unit_015/CONTINUOUS_OPERATION.md)は採用機能の連続運転を所有し、いずれもU07の完了を待たない。

## 5. TDD Test List・対象ファイル

専用機能のTDD項目・製品変更ファイルは予約しない。通常指示、停止、Goal操作の試験はunit_061・062、保存参照からの復帰はU08へ所属させる。今回の対象は本書と関連する範囲・依存・検証計画の文書のみ。

## 6. 再検討の着手条件・先送り

通常指示と共通停止では満たせない具体的な利用要求が確認されたときに再検討する。その時点でゲーム内の成功確認方法、モデルへ任せる判断、Gigasに必要な追加保証を定義してから着手を決める。旧案をそのまま復活させず、担当は再検討する作業単位とし、初期版の期限は置かない。
