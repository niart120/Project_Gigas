# U09 記憶整理・退避・復元 親仕様

## 1. 目的・状態・起点

依頼完了後と明示操作による記憶整理を、退避・排他・正常採用・失敗時復元まで含む一つの利用フローとして完成させる。

状態: **planned（未着手）**。本書は2026-11-11の工程計画であり、この工程の方式調査・詳細設計・製品実装・実接続検証を完了した記録ではない。初期設計の既存調査は着手時の材料とし、採用版の動作確認と区別する。

| 起点 | 内容 | 参照 |
|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 攻略が終わった利用者が整理結果を次の依頼で使う。整理が失敗・中断した場合やアプリを再起動した場合には、元の記憶へ復元してから次の攻略を始められる。

## 2. 前提と着手条件

[U08](../unit_013/RESUME.md)までの開始・停止・読込と、[U06](../../wip/unit_011/GOAL_EXECUTION.md)の依頼完了・記憶入口が前提。U01の設定保存やU04のプロジェクト保存を、記憶の退避・復元が実装済みの根拠にしない。

親仕様は工程の受入条件を所有する。着手時に本ディレクトリを`spec/wip`へ移し、最初の子仕様を具体化する。子の番号を先行予約せず、作業仕様を複製しない。必要な公開経路・機器条件が成立しなければ、その条件へ依存する実装は進めず設計判断を更新する。

## 3. 対象範囲・対象外

対象: 攻略と別の整理スレッド、整理用指示と対象記録の範囲、攻略との排他、memory一式の退避、整理中の印と退避先の永続化、書込終了待ち、正常採用、追加・削除・改名を含む復元、再起動後の未完整理、全開始経路への利用可否の接続を扱う。

対象外: ゲーム入力・攻略Goalの整理スレッドへの提供、原記録・画像・依頼完了の巻戻し、中途半端な整理結果の採用、プロジェクト横断統合、汎用履歴管理、常時・定期的整理、攻略Skillsの自動生成は行わない。

## 5. 冒頭の調査・設計

| 対象 | 調べる・決めること | 成果と進行条件 |
|---|---|---|
| 整理と書込終了 | 別スレッドへ渡す権限・記録範囲・指示、攻略側と整理側の書込が終わったことの確認方法を設計する | 待機の取消しだけで実処理の終了としない。確認できない間は復元も次の攻略も開始しない |
| 退避と復元 | 対象ファイル、memory外の退避先、管理情報の配置、追加・削除・改名、復元途中の失敗・再試行を設計する | 退避失敗なら整理を始めず、途中でプロセスが止まっても未完を識別できる。ファイル権限による完全隔離を未検証のまま保証しない |
| 採用と開始条件 | 正常終了の確定、未完の印の解消、依頼完了との分離、次の攻略への記憶の読み直しを設計する | 起動・新規依頼・明示再開・プロジェクト切替を含む全入口で同じ利用可否を確認する |
| 保存と指示の結合 | 新しい管理項目・イベントと整理指示の同梱・配送を具体化する | U04以来の保存部品へ追加し、退避単体の成功だけで整理全体の完了にしない |

## 6. 子工程の分割と順序

| 子工程候補 | 開始条件 | 到達点 |
|---|---|---|
| M0 整理・復元の契約 | U08の開始経路とU02/U07の書込終了に関する調査・確認結果 | 採用版で整理スレッドの書込終了を確認する経路を検証し、対象、排他、退避、終了判定、復元・再試行の順序を決める |
| M1 退避・復元と未完記録 | M0 | 機器・モデルなしで追加・削除・改名、失敗途中、再読込時の未完識別を確認する |
| M2 整理スレッドと全入口の結合 | M1とU06/U08 | 正常採用、失敗・中断後の復元、再起動、次の攻略での読み直しを確認する |

これは分割方針であり、子仕様・API・全テストの先行作成ではない。調査で変更理由が生じたら本書と影響する初期設計を更新する。

## 7. 振る舞い仕様・TDD Test Listの受入観点

| 観点 | 工程全体で確認する振る舞い | 主な検証 |
|---|---|---|
| 起動と排他 | 依頼完了後または攻略停止中の明示操作だけで整理し、攻略と同じ記憶への書込を重ねない | T12 |
| 退避失敗 | 退避の成立前に整理スレッドを動かさず、元の記憶を保持して理由を示す | T12・T19該当範囲 |
| 復元 | 失敗・中断後は整理側の書込終了を確認し、追加・削除・改名も含めてmemoryを元へ戻す。原記録・画像・依頼完了は戻さない | T12・T19該当範囲 |
| 未完と再起動 | 整理・復元の未完を読込時に識別し、復元できない間は新規開始・再開を許可しない | T12・T18との結合 |
| 採用後の利用 | 成功後または復元後の現状メモを次の攻略で読み直す。復元完了だけで攻略を自動開始しない | T11・T12・T20 |

親では受入観点のみを定める。詳細なTDD Test List、red/greenの履歴、具体的なAPIと故障注入点は、着手する子仕様へ記載する。文書の見出し・状態語・チェック欄の一致を製品テストにはしない。

## 8. 対象ファイル候補

`src/gigas/storage/`・`app/`・`runtime/codex/`・`ui/`・`prompts/`、対応する試験と整理・復元手順のdocs。退避形式と具体的な管理項目はM0で決める。

公開APIの変更時はdocstringと利用者向けdocsを更新し、型境界・docstringの対応skillを使う。GUIには必要なラベル・状態・エラーとCodex/ユーザー由来の文章を表示し、アプリ独自の説明本文はdocsへ置く。

## 9. 検証計画と未実行事項

一時プロジェクトでファイル構成の変化・部分失敗・再起動相当の再読込を確認し、同じ保存部品へ整理スレッドを接続する。Codex要求待機の取消しと書込の収束を区別する実接続確認を行う。整理指示と案内の更新をT20へ含める。

| 確認 | 現在の結果 | 実施時の扱い |
|---|---|---|
| 方式調査・設計判断 | not run | 本工程未着手。採用版・機器・根拠と未確認事項を子仕様へ記録する |
| 製品の単体・結合試験 | not run | 実装時に対象のpytest、ruff、tyをAGENTS.mdに従って実行し、検査する契約を記録する |
| 整理スレッド・ファイル更新・開始GUI | not run | 採用ランタイムで整理側の書込終了、正常採用、失敗・中断後の復元を確認する。GUIを含む開始・再開の全入口で未完整理による制限と記憶の読み直しを確認する |
| 整理用スレッドからの物理入力 | not applicable | 整理スレッドにはゲームMCPと攻略Goalを渡さない。権限を与えないことは結合試験で確認し、実機操作を整理の受入条件にしない |
| 依存・公開API・配布 | not run | 変更する子仕様でuv lock --check・uv buildを含める。指示資材変更はT20も確認する |

親仕様の文書検査は工程計画の整合確認であり、上記の製品検証を実行済みにしない。工程完了には本書の必要な実接続・実機確認の根拠が必要で、模擬試験の成功だけで置き換えない。
