# U09 専用記憶整理 親仕様（初期版対象外）

## 1. 目的・状態・起点

状態: **planned（初期版対象外・必要時に再設計）**。2026-11-13の[契約整理M0](../../wip/unit_054/KISS_SIMPLIFICATION.md)で、専用の記憶整理を初期版から外す方針を承認した。本unitは削除・完了扱いにせず、再検討先として保持する。調査・製品実装・接続検証には未着手である。

2026-11-11の計画にあった依頼完了後の自動整理、別整理スレッド、全memory退避、失敗時の自動復元、再起動後の未完整理復旧、全開始経路への復旧条件の接続は、初期版の要求から撤回した。

## 2. 前提と着手条件

記憶が読みづらい、通常Goalによる更新や停止中の手編集では足りない等の具体的な利用上の問題が示され、専用機能を再採用する判断が行われた場合にだけ着手候補とする。U08完了だけでは着手条件を満たさず、U10は本工程を待たない。

再採用時は本書の範囲・受入条件を先に改訂する。調査・設計へ着手するときに同じunitをwipへ移し、その時点で必要な子作業だけを作る。

## 3. 対象範囲・対象外

現在の対象は初期版からの除外と、再検討条件の保持だけである。通常Goalによるmemory更新、停止して書込処理が収束した後の利用者編集、次の明示開始・再開での現状メモ読込は既存の攻略・再開契約に残す。

専用の自動・手動整理、候補生成API・専用フォルダー・採用UI、退避・復元エンジン、未完管理、復旧待ちによる開始禁止は作らない。通常memory更新に対する自動backup/rollbackも保証しない。

利用上の問題、整理対象、利用頻度、通常の更新では不足する点を確認する。必要なら既存memoryを変更しない明示生成だけの方式から比較するが、採用方式は予約しない。自動復元や汎用トランザクション基盤を従来案から継承しない。

## 6. 子工程の分割と順序

現在は子工程を作らない。再採用判断と方式設計後、成立確認に必要な一作業だけを具体化する。旧退避・復元・全入口結合のM1/M2案は実装順序として使わない。

## 7. 振る舞い仕様・TDD Test List

専用整理の製品受入・TDD項目は現在対象外とする。旧T12は過去仕様からの参照番号として残し、初期版の必須gateから外す。再採用時に選んだ利用場面から受入を作り、旧異常系の組合せを一括復活させない。
