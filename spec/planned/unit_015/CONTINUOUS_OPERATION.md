# U10 Windows連続運転 親仕様

## 1. 目的・状態・起点

完成した各機能をWindows実機で組み合わせ、短い依頼から数時間の運転へ広げる。動作した条件と未確認条件を記録し、実装不具合とモデルの攻略結果を区別する。

状態: **planned（未着手）**。本書は2026-11-11の工程計画であり、この工程の方式調査・詳細設計・製品実装・実接続検証を完了した記録ではない。初期設計の既存調査は着手時の材料とし、採用版の動作確認と区別する。

| 起点 | 内容 | 参照 |
|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 利用者が継続攻略中に介入・停止し、手動操作やアプリ再起動を挟んで再開する。依頼完了後の整理を経て次の依頼へ進み、同じ構成で連続運転できることを確認する。

## 2. 前提と着手条件

[U02](../unit_007/CODEX_CONNECTION.md)〜[U09](../unit_014/MEMORY_MAINTENANCE.md)の必要な単体・結合・実接続確認が済んでいること。映像はU03、画像付きMCPはU04、物理入力と解除はU05、GoalはU06で確認済みでなければ、その不足を該当工程へ戻す。U10を最初の実機確認工程にはしない。

親仕様は工程の受入条件を所有する。着手時に本ディレクトリを`spec/wip`へ移し、最初の子仕様を具体化する。子の番号を先行予約せず、作業仕様を複製しない。必要な公開経路・機器条件が成立しなければ、その条件へ依存する実装は進めず設計判断を更新する。

## 3. 対象範囲・対象外

対象: 機器・OS・Python・SDK等の構成記録、代表利用場面の一連の確認、連続運転、停止応答・入力観測対応・記録量・メモリ・遅延・終了時の残存処理の測定、未確認条件と不具合の切分けを扱う。

対象外: ゲーム攻略能力の研究用ベンチマーク、全ゲーム・全機器の保証、無測定の性能保証、長時間試験のための自動課金切替、初期範囲外の機能追加、リリース・公開手続は含めない。

## 7. 振る舞い仕様・TDD Test Listの受入観点

| 観点 | 工程全体で確認する振る舞い | 主な検証 |
|---|---|---|
| 運転中の契約 | 継続中も操作・観測・依頼の対応を追え、保存失敗・明示的障害で入力を止める | T01〜T10・T15〜T17の統合確認 |
| 停止と再開 | 即時停止・計画的終了後、手動変更やアプリ再起動を挟んでも旧入力を再送せず現在画面を使う | T11・T13・T14・T18 |
| 依頼完了と整理 | 依頼完了を記録して整理へ進み、成功または必要な復元後に次の攻略で記憶を読み直す | T12 |
| 継続性の根拠 | 測定した時間・機器・依存版と、遅延・記録量・資源・終了状況を残す。未確認条件を成功に含めない | Windows実機・運転記録 |

親では受入観点のみを定める。詳細なTDD Test List、red/greenの履歴、具体的なAPIと故障注入点は、着手する子仕様へ記載する。文書の見出し・状態語・チェック欄の一致を製品テストにはしない。

## 8. 対象ファイル候補

`tests/acceptance/`の再利用可能な手順・必要最小限の補助、各作業仕様の検証結果、利用者向け制約のdocs。実ログ・認証情報・個人のプロジェクト画像を固定fixtureとしてcommitしない。製品不具合の修正は原因を持つ子仕様へ戻して範囲を定める。

公開APIの変更時はdocstringと利用者向けdocsを更新し、型境界・docstringの対応skillを使う。GUIには必要なラベル・状態・エラーとCodex/ユーザー由来の文章を表示し、アプリ独自の説明本文はdocsへ置く。

## 9. 検証計画と未実行事項

対象構成で実機・実アカウントの短い総合確認を終えてから連続時間を伸ばす。モデルが目標達成できなかった場合と、操作・保存・停止契約の違反を分ける。確認のたびに全自動試験を機械的に繰り返さず、修正した範囲と未解決懸念に対応するゲートを選ぶ。

| 確認 | 現在の結果 | 実施時の扱い |
|---|---|---|
| 方式調査・設計判断 | not run | 本工程未着手。採用版・機器・根拠と未確認事項を子仕様へ記録する |
| 製品の単体・結合試験 | not run | 実装時に対象のpytest、ruff、tyをAGENTS.mdに従って実行し、検査する契約を記録する |
| Windows実機での総合・連続運転 | not run | 固定した機器・SDK・認証構成で、短い総合確認から数時間へ延長する。介入・停止・再開・整理、遅延・記録量・資源・終了状態を測定する |
| 依存・公開API・配布 | not run | 変更する子仕様でuv lock --check・uv buildを含める。指示資材変更はT20も確認する |

親仕様の文書検査は工程計画の整合確認であり、上記の製品検証を実行済みにしない。工程完了には本書の必要な実接続・実機確認の根拠が必要で、模擬試験の成功だけで置き換えない。
