# U08 停止・再起動後の再開 親仕様

## 1. 目的・状態・起点

保存された依頼・記憶と現在画面から、同じスレッドまたは新しいスレッドで攻略を再開する。過去の操作を再送することなく、旧処理の収束と新しい入力世代を扱う。

状態: **planned（未着手）**。本書は2026-11-11の工程計画であり、この工程の方式調査・詳細設計・製品実装・実接続検証を完了した記録ではない。初期設計の既存調査は着手時の材料とし、採用版の動作確認と区別する。

| 起点 | 内容 | 参照 |
|---|---|---|
| 要求 | 2026-11-11の工程再編方針。U01の成果と未実装機能を分け、調査・設計から各工程を始める | [実装計画](../../initial/05-implementation.md) |
| 規約 | plannedから着手する仕様を選び、製品実装と接続検証を区別する | [AGENTS.md](../../../AGENTS.md)・[配置と運用](../../initial/06-repository.md) |

利用場面: 利用者が即時停止や計画的終了の後、またはアプリ再起動後に明示的な再開を選ぶ。ゲームを手動で進めたりリセットした場合も、現在画面を確かめて続ける。

## 2. 前提と着手条件

[U06](../unit_011/GOAL_EXECUTION.md)の依頼・Goal・記憶入口とU05の旧世代失効が前提。即時停止後の再開はU06から着手できる。[U07](../unit_012/PLANNED_STOP.md)は計画的終了後の再開確認に必要であり、その経路を含む本工程全体の完了前に成立させる。

親仕様は工程の受入条件を所有する。着手時に本ディレクトリを`spec/wip`へ移し、最初の子仕様を具体化する。子の番号を先行予約せず、作業仕様を複製しない。必要な公開経路・機器条件が成立しなければ、その条件へ依存する実装は進めず設計判断を更新する。

## 3. 対象範囲・対象外

対象: 停止中の読込、保存された依頼・実行・ランタイム参照の確認、同じスレッドとGoalの再開、スレッドを利用しないコールドスタート、現在画面の配送、新しい実行世代、未完・破損記録の扱い、GUIの再開とプロジェクト選択を扱う。

対象外: 自動再開、利用枠回復による自動開始、過去操作の再送、ランタイムの状態修復・自動再起動、ゲームセーブの復元、記憶整理の退避・復元は行わない。記憶復元による開始条件はU09で同じ開始経路へ追加する。

## 5. 冒頭の調査・設計

| 対象 | 調べる・決めること | 成果と進行条件 |
|---|---|---|
| 再開に必要な保存情報 | 依頼・実行・スレッド・Goal参照、案内と現状メモ、未完操作・破損ログ、初期化しない読込を点検する | 再起動後に必要な情報だけを追加する。正常に読める範囲と欠落・不明を区別し、原記録を保つ |

| 旧処理と新実行 | 旧入力・旧書込の終了、旧世代無効化、新しい観測・接続世代、開始条件とGUI操作を設計する | 現画面と記憶を渡す前に過去入力を許可しない。復旧不能を理由付き停止として表示する |

## 7. 振る舞い仕様・TDD Test Listの受入観点

| 観点 | 工程全体で確認する振る舞い | 主な検証 |
|---|---|---|
| 明示的開始 | 停止・起動直後は入力を閉じ、再開操作がなければ攻略を始めない | T11・T18 |
| 同じ依頼の再開 | 同じスレッド・Goalの利用とコールドスタートを区別し、依頼・採用記憶・新しい観測を渡す | T11・T13の再開側・T18 |
| 旧入力と失敗 | 旧処理が収束しない場合は再開せず、古い要求と未完操作を再送しない。再開要求の結果不明を成功扱いにしない | T03・T17・T18 |
| 記録と現画面 | 既存記憶・原記録を無断初期化せず、ゲームがリセット・手動変更されても現画面との照合をCodexへ指示する | T09・T11・T19該当範囲 |

親では受入観点のみを定める。詳細なTDD Test List、red/greenの履歴、具体的なAPIと故障注入点は、着手する子仕様へ記載する。文書の見出し・状態語・チェック欄の一致を製品テストにはしない。

## 9. 検証計画と未実行事項

保存・破損・未完記録は一時プロジェクトで確認する。Codexの同一スレッドと新規スレッドの経路は実ランタイムで確認し、実機で手動操作・ゲームリセット・アプリ再起動後の現在画面を使う。自動試験の旧世代拒否を、実機の復元成功として扱わない。

| 確認 | 現在の結果 | 実施時の扱い |
|---|---|---|
| 方式調査・設計判断 | not run | 本工程未着手。採用版・機器・根拠と未確認事項を子仕様へ記録する |
| 製品の単体・結合試験 | not run | 実装時に対象のpytest、ruff、tyをAGENTS.mdに従って実行し、検査する契約を記録する |
| スレッド再開・現在画面・再開GUI | not run | 同一スレッドと新規スレッドを採用ランタイムで確認する。実機の手動変更・リセット、アプリ再起動、計画的終了後に新しい観測を使って再開する |
| 依存・公開API・配布 | not run | 変更する子仕様でuv lock --check・uv buildを含める。指示資材変更はT20も確認する |

親仕様の文書検査は工程計画の整合確認であり、上記の製品検証を実行済みにしない。工程完了には本書の必要な実接続・実機確認の根拠が必要で、模擬試験の成功だけで置き換えない。
